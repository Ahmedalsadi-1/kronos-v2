# 01 - Electron startup and shutdown

Scope: `emain/emain.ts`; read `emain/AGENTS.md`. Static review only; no runtime failure reproduced.

## Recommendations

1. **P1: Make startup stages explicit, fail fast, and surface recovery instructions.** Observed: `emain/emain.ts:448-454` catches server launch failure and proceeds to readiness; `:475` uses a fixed 10 ms delay; `:476-483` catches RPC initialization failure and immediately calls config RPC. Hypothesis: a launch or handshake fault leaves a confusing startup state or generic exit. Introduce named stages with a bounded handshake, distinguish mandatory server/RPC from optional agent services, and show stage/error plus retry/log location. Reference [VS Code main startup](https://github.com/microsoft/vscode/blob/main/src/vs/code/electron-main/main.ts): explicit initialization boundaries, performance marks, error handling and user-resolvable startup errors. Acceptance: injected server launch failure, missing readiness, RPC failure each produces one bounded failure path; optional Hermes failure still opens the workspace; remove time-based readiness inference.

2. **P1: Await an idempotent shutdown barrier for managed children.** Observed: `emain/emain.ts:302-308` invokes manager shutdown without awaiting it; `:329-333` waits only via a fixed timeout, and repeated quit paths re-enter handlers. Hypothesis: child cleanup can race process exit or be invoked repeatedly. Adapt [VS Code lifecycle joiners](https://github.com/microsoft/vscode/blob/main/src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts), which caches one shutdown promise and settles registered cleanup promises. Acceptance: repeated quit/signal produces one cleanup per manager; fast children complete before exit; hung child cannot block beyond an explicit deadline; validate Windows and macOS branches separately.

3. **P2: Record per-stage startup timing before optimizing daemon placement.** Observed: `emain/emain.ts:423,454` logs only elapsed server readiness; `:483-502` config, window restoration and updater await sequentially. No bottleneck established. Borrow [VS Code startup performance marks](https://github.com/microsoft/vscode/blob/main/src/vs/code/electron-main/main.ts), instrument server spawn/ready, RPC handshake, config, first usable window and updater. Acceptance: 20 cold/warm launches yield stage p50/p95; defer a stage only after measurements prove it delays usability; diagnostics avoid argv, secrets and workspace contents.
