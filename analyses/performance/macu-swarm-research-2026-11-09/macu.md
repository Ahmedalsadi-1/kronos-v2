MACU integration findings (read-only)

Upstream: https://github.com/kohjingyu/multi-agent-computer-use/tree/5b1b8f91dfc5dc66a2f06af4b443b3009a9cd105, Apache-2.0 (LICENSE). Shallow clone confined to /tmp/kronos-macu-research. No runtimes, dependencies, or tests were started.

What it is: Real LLM graph generation, validation-driven retries, ready-queue priority by downstream fan-out/dependencies, parallel CUA subprocess dispatch, evidence-driven graph edits and aggregation. Ready work launches without waiting for whole topological levels. run_macu.py:568–625 polls processes, checks budgets and dispatches; :627–640 and :771–792 replan on completion and spare capacity; :673–760 proposes add/remove/modify/cancel and persists accepted snapshots. utils/graph_utils.py:593–874 validates changes against frozen nodes, checks acyclicity and aggregation before mutating the graph. Live review uses sentinel files (run_macu.py:642–671). Real worker dispatch is tied to OSWorld/Python 3.12 and VMware or Apptainer/QEMU (README.md:32–53; utils/macu_runtime.py:181–326,1035 onward), including VM boot/reuse, file transfer and subprocess traces. Ad hoc --task still requires the VM path (README.md:264–269). No drop-in KronOS adapter or supported general-purpose coordinator API was found.

Confirmed unsuitable semantics for production dependencies: utils/macu_runtime.py:782–786 records a nonzero subprocess exit as an error string, then run_macu.py:619–625 calls materialization; materialization at utils/macu_runtime.py:835–863 adds the node to completed. Timeout uses this same path (:932–962). Readiness then admits both completed and cancelled parents (:964–978). A downstream effect can therefore start without its prerequisite succeeding; MACU may interpret those failures as useful context for replanning, but KronOS must distinguish them from successful dependencies. Initial graph validation errors remaining after retries only warn in utils/macu_runtime.py:567–576; this is not fail-closed. Replan quota counts accepted nonempty edits, not attempted LLM calls (run_macu.py:677–687,746–749). Replan and follow-up model calls are synchronous in the scheduler, so model latency can delay dispatch/cancellation checks. Actual latency or race incidence on KronOS is unmeasured. MACU cancellation terminates/waits/kills subprocesses and writes a sentinel (utils/macu_runtime.py:713–740); no verified reconciliation of external effects. Graph snapshots/logs are diagnostic: task loading regenerates graph (:452–453); batch completion markers skip whole tasks and .claimed files require manual stale cleanup (:1873–1899,1952–1997). This is not restartable execution.

Recommended integration (use actual MACU): Pin and attribute the upstream implementation and extract its graph/planner/replan core behind a small, versioned Python planning sidecar; expose plan/replan over typed stdio requests, driven by KronOS evidence and capability inventory. Keep MACU graph validation and prompts as sourced implementation with explicit target/authority and provider callback adaptations. KronOS main remains authoritative for scheduling ready branches, lifecycle, target lease, persistence, effects and observation. An intact CLI sidecar has largest OSWorld coupling and duplicative control plane; Python orchestration of production effects would require a substantially larger adapter. A source-preserving TS port of the small graph/planner core can avoid Python distribution if benchmarked sidecar overhead or packaging proves unacceptable; preserve provenance, behavior fixtures, and Apache notices.

Concrete requirements:
1. Validate MACU initial and revised plans against a closed action/capability catalog before dispatch. Bind each node to exact workspace/tab/block or device/VM/app identity and generation; acquire target leases independently of model text. emain/kronterm-tool-server.ts:675–733 already brokers delegation prepare/cancel/finish and token resolution; emain/delegation-policy.ts:59–103,126–149 scopes children and checks sandbox control generation. The existing sandbox-exclusive lease is not a general widget/device lease; serialize by underlying effect resource, including shared desktop input or shared browser storage where applicable.
2. Host owns target adapters. Reuse workflow runtime inventory and bound prompt/evidence conventions (emain/workflow-runtime.ts:105–161,204–221). Reuse ACP workers and approved tool surface, not MACU desktop commands (emain/acp/acp-agent-manager.ts:153–164,560–619,728,893; emain/acp/acp-harness.ts:311). Independent Computer engine is native macOS accessibility only (emain/computer-workflow-engine.ts:37–78); browser widgets, other widgets, Android, iOS and Linux guest backends require their own capability/readiness checks and observation/action/verification adapters. Never fall back from a device or guest to host input.
3. Implement ready queue of verified-success dependencies and explicit opt-in for collecting failed/partial outcomes. Preserve fan-out prioritization and max parallelism from utils/macu_runtime.py:964–978,1035 onward; test independent target concurrency, same target exclusion, failed prerequisite and aggregate partial-result behavior. emain/workflow-store.ts:598–632 has a max of three concurrent runs plus computer/workflow keys and success-only DAG readiness, but executes one step per run; do not mistake current workflow runs for parallel branches.
4. Apply replan patches at a compare-and-swap revision, revalidate graph and scope, freeze completed/running nodes except explicit cancellation, and cap model calls/time/cost independently of accepted patches. Decouple planning from scheduling so unaffected branches can proceed; dedupe/coalesce replan triggers. Replan may narrow scope only; new targets require the existing authority path. Verify cancellation by revoking child authority, aborting ACP/tool work and fencing late events before releasing leases. Compare utils/graph_utils.py:593–874 and emain/delegation-policy.ts:164–179.
5. Persist a durable per-node attempt/operation ledger before dispatch and after verified outcome. On crash/pause/timeout mark affected operations uncertain, reobserve/reconcile before replay, reject stale generation/results and resume only authorized nodes. Existing emain/workflow-store.ts:179,507–520,653–667 supplies interrupted-step reconciliation but must represent multiple in-flight nodes and partial completion. Test restart, duplicates, stale revision, cancellation vs. late completion, and partial-write recovery. Measure end-to-end wall time/critical path, verified success, repeat effects and planner costs against one-worker baseline on scoped fixtures before making speed/reliability claims.
