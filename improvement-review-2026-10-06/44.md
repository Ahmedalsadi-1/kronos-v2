# 44 - Configuration hot reload (pkg/wconfig)

Priority: P1. Strongest improvement: make configuration reload converge after directory changes and coalesce event bursts before publishing a new snapshot.

## Evidence and scope

Read the nearest `pkg/wconfig/AGENTS.md`; its referenced parent `pkg/AGENTS.md` is absent. Sampled the watcher and its config enumeration path. At `pkg/wconfig/filewatcher.go:53`, subdirectories are added once during initialization; missing directories are deliberately ignored at line 56. At line 153, every event whose pathname is not a JSON file is rejected. Consequently, creation of a previously missing configuration subdirectory cannot install a new watch through this code. `pkg/wconfig/settingsconfig.go:743` enumerates such subdirectories, confirming that separate directory watches are part of the design.

Observed: `filewatcher.go:169` rereads and publishes the entire configuration for every accepted event, under the watcher mutex (`:146`). There is no debounce, equality check, or watch reconciliation in this path. Hypothesis: bursty editor saves cause redundant reloads/handler executions, and edits inside a directory created after startup remain invisible until restart. Neither behavior was reproduced at runtime during this read-only review. A second follow-up risk is `Close` setting `w.watcher` to nil while the goroutine repeatedly accesses that field (`:78`, `:83`, `:108`); confirm with race tests before assigning a separate defect.

## Proven repository pattern and fit

The existing upstream [fsnotify README](https://github.com/fsnotify/fsnotify/blob/main/README.md) explicitly documents that subdirectories require their own watches and recommends watching parent directories for atomic editor replacements. Its [dedup example](https://github.com/fsnotify/fsnotify/blob/main/cmd/fsnotify/dedup.go) demonstrates resettable timers to coalesce events. Adapt these two patterns inside the existing Go watcher; a wholesale configuration library replacement is unnecessary. Upstream has a [BSD three-clause license](https://github.com/fsnotify/fsnotify/blob/main/LICENSE); retain notices if copying implementation code. Pin the consulted revision during implementation rather than depending on moving main links.

## Implementation and acceptance gate

Handle known-directory create/remove/rename events before JSON filtering; reconcile required watches and trigger one reload. Add a bounded debounce, cancel pending timers on shutdown, and publish only when the resulting snapshot changes, while preserving configuration error reporting. Capture the underlying watcher locally in the consumer goroutine and make Start/Close lifecycle explicit.

Gate: focused temporary-directory tests covering creation after startup, atomic file replacement, directory recreation, multi-event writes, malformed JSON followed by repair, and concurrent shutdown. Run these under `go test -race ./pkg/wconfig`; require eventual correct configuration and no post-close notifications. Do not assert exact OS event counts. No builds, product edits, or tests were run in this review.
