# Review 12: OS workspace state recovery

## Strongest finding: malformed persisted layouts can abort initialization (P1)

Observed in source: `frontend/app/tab/os-workspace-model.ts:220` casts metadata directly into a typed state. Migration dereferences every `window.bounds.width` and `.height` at lines 283-290 without validating the window or bounds. A JSON-valid payload such as `{version:4, windows:{browser:{blockId:"browser"}}}` therefore throws before `makeInitialOSModeState` can supply defaults (lines 311-317). Object normalization similarly assumes an array (lines 254-256); camera and scene receive no structural validation (lines 338-348). Minimum clamping does not reject non-finite values.

Hypothesis: partial/older metadata, external edits, or an interrupted migration could prevent a workspace opening. No incident or runtime reproduction was established; this was read-only inspection, with no builds or test execution.

Priority: decode metadata as unknown, validate each record, preserve healthy windows, and replace invalid geometry/camera/scene fields with explicit defaults. Contain migration failures at the hydration boundary rather than trusting TypeScript casts. Preserve original metadata for recovery instead of silently overwriting it.

Acceptance: fixtures with missing bounds, null windows, non-array objects, malformed scene, non-finite geometry, and invalid camera zoom initialize without throwing; valid windows retain positions and identities; unsupported future versions retain the current explicit fallback behavior. Existing migration fixtures at `frontend/app/tab/os-workspace-model.test.ts:69` remain valid.

## Additional priority: reconcile saved overview scene (P2)

Observed: reconciliation validates only `scene` (model lines 398-405), while overview records `previousScene` (583) and restore accepts it verbatim (589). Sequence: focus A, overview, remove A, reconcile, restore. The model restores focused A despite its removal; layout then hides remaining windows (708-712). Likewise a removed group can be resurrected. User-visible blanking is a hypothesis pending UI reproduction.

Acceptance: normalize both current and saved scenes against live noncollapsed windows/groups; restoring overview after deletion or minimization lands in a valid scene with visible surviving windows. Add reducer sequence fixtures for focused and grouped cases.

## Verified upstream pattern and fit

[pmndrs/zustand persist source](https://github.com/pmndrs/zustand/blob/main/src/middleware/persist.ts) accepts migration input as `unknown`, separates migration from merge, and catches hydration failures with an error callback. This supports a contained hydration boundary; it does not itself provide KronTerm geometry validation. Verified by browsing primary source on 2026-10-06. Adopt the pattern locally in the existing pure model/Jotai architecture, without adding Zustand. Maintenance requires explicit version fixtures and one shared scene validator. [MIT license](https://github.com/pmndrs/zustand/blob/main/LICENSE) permits adaptation; retain its notice if copying substantial source. Conceptual reuse avoids dependency and license overhead.
