## Strongest improvement: give backfill requests explicit lifecycle ownership

**P2 - Separate shared network work from each caller's session validity and delivery.** `transcript-backfill.ts:108` stores one promise per durable session id. At `:124-125`, a second caller receives that promise immediately; its own `isCurrent` and `applyOlderPage` callbacks never participate. The eventual response is checked only against the first request at `:147`, then applied only through that first callback at `:156`. Consequently the promise represents a first-caller-specific operation, although the map is keyed as reusable session-wide work. This is an observed ownership mismatch. A visible lost-backfill race when two chat owners request the same session, or when a session is left and revisited during a pending request, remains unverified: caller lifetimes and cache behavior need a controlled reproduction.

Keep the useful single-fetch behavior, but make ownership explicit. Either have a shared fetch deliver data to independently validated subscribers, or apply once to a canonical session cache with a generation guard, then let views subscribe to that cache. Retain the existing stale-response protection and row-id deduplication. Dispose each subscriber on session change/unmount, and remove shared entries on settlement; decide explicitly whether the final subscriber leaving aborts transport or merely discards its response. Do not add a second state library for this.

## Proven repository pattern and fit

The established [VS Code DisposableStore/toDisposable implementation](https://github.com/microsoft/vscode/blob/main/src/vs/base/common/lifecycle.ts) supplies the transferable pattern: each owner registers independently disposable resources, with idempotent cleanup. It is a lifecycle ownership reference, not a ready-made transcript pagination implementation. VS Code [source license](https://github.com/microsoft/vscode/blob/main/LICENSE.txt) is MIT. Implement a small local equivalent or preserve applicable notices if copying substantial code; importing VS Code internals would add unnecessary coupling. These links were verified by the parent review catalog and section 02. Fresh browsing verification was unavailable following the reported network permission revocation; no bypass was attempted. Pin the reviewed upstream commit before implementation.

## Acceptance gate

Use a deferred mocked page response. Two owners requesting the same durable session must produce one network call; invalidate the first owner before resolving; the valid second owner must receive the page exactly once and the stale owner must receive none. Also cover both owners invalidating, rejection followed by retry, and revisit with a new generation. Confirm pagination advances once per applied page, duplicate rows are absent, and no subscriber/map entry survives settlement or disposal. This gates the ownership behavior without asserting an unmeasured performance improvement.
