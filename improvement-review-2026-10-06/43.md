# 43 — WPS event delivery

Priority: P1 investigation, then P2 implementation unless reproduction establishes a user-visible stall. Scope: `pkg/wps`, sampled broker publish and router delivery path. Read `pkg/wps/AGENTS.md` and the repository WPS event guide; its referenced parent `pkg/AGENTS.md` is absent.

## Strongest improvement

Give event delivery a bounded, observable slow-consumer contract. `pkg/wps/wps.go:226` publishes synchronously; its loop at line 236 calls every route's `SendEvent` sequentially. The interface at line 20 returns neither an error nor a delivery outcome. The real implementation at `pkg/wshutil/wshrouter.go:194` silently returns when a route is unavailable or JSON serialization fails, and delegates successful sends to the link transport. Thus the broker cannot distinguish accepted, missing-route, failed-encoding, overloaded, or delivered events.

Observed: synchronous dispatch, lack of an outcome contract, and silent early exits. Hypothesis requiring transport inspection and reproduction: a slow link can delay other subscribers or publishers, or transport buffering can hide overload. This review does not establish that transport blocks, grows without bounds, or drops events. Another observed concern is that `MaxPersist` limits each history bucket, while `PersistMap` at line 217 retains independently keyed scopes with no eviction in this file; assess this separately with realistic block churn.

## Proven repository pattern and fit

Use the maintained Go NATS client as a design reference: [subscription implementation](https://github.com/nats-io/nats.go/blob/main/nats.go), [subscription tests](https://github.com/nats-io/nats.go/blob/main/test/sub_test.go), and the project's [slow-consumer operational documentation](https://github.com/nats-io/nats.docs/blob/master/running-a-nats-service/nats_admin/slow_consumers.md). Its pattern exposes pending message/byte limits and slow-consumer reporting. This is a suitable Go event-system reference; it does not imply that KronTerm needs a network broker or NATS dependency. NATS Go uses Apache-2.0; verify the exact pinned revision's [license](https://github.com/nats-io/nats.go/blob/main/LICENSE) before copying code, because the license page failed to render in this review. Prefer adapting behavior rather than copying internals.

## Implementation plan and gate

First trace transport queue capacity and send blocking, recording publish latency and per-route queue depth without payloads. Define delivery outcomes and per-event semantics: state refresh notifications may coalesce and trigger snapshot recovery; lifecycle/control events require preserved order and explicit failure handling. If the reproduction warrants it, add bounded per-route dispatch with cancellation on route teardown, avoiding one goroutine per publish.

Acceptance gate: a fake stalled subscriber must not prevent a healthy subscriber from receiving updates; saturation must produce a measurable outcome and recovery path; repeated subscribe/unsubscribe must leak neither workers nor queues; concurrent publish/unsubscribe must pass `go test -race ./pkg/wps/...`. Confirm existing ordering and scope deduplication before rollout. No product code changed and no builds or tests were run.
