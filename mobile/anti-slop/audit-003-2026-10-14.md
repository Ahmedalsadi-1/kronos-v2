# Mobile controls and workspace: after-build audit

Direction: the user's minimal chat reference, compact widget icons, Safari-style browsing, and a file explorer/editor. ENERGY 1 / RHYTHM 2 / MOTION 1. This is an iPhone Labs source and browser preview, not a verified native release.

## Numbered findings

1. HIGH, R-35: native Safari presentation and system keyboard positioning remain unverified on the physical phone. USB pairing succeeds and a development signing identity exists, but full Xcode/iOS SDK is absent. Capacitor sync copies assets; it does not compile Swift or install an app.
2. HIGH, R-36/R-38: the console tool VM and graphical desktop are still separate guests. Settings disclose this. Files/Code reflect the actual saved console VM's /mnt filesystem; they must not be represented as the graphical desktop's disk.
3. HIGH, R-36: pairing adapts Orca's source-informed setup sequence but uses KronTerm LAN pairing. Orca encrypted transport and pinned-key QR offers have not been transplanted. The pairing screen identifies LAN use; see ../ORCA-PAIRING-REFERENCE.md.
4. MEDIUM, R-26: embedded browser history tracks addresses submitted through the app. Cross-origin page links cannot report navigation to the parent. Native Safari view opens the selected address in a separate modal; it does not share preview tab state.
5. MEDIUM, R-35: direct desktop taps and keyboard events are wired, with a compact trackpad fallback. Exact pointer placement depends on guest mouse support/acceleration; physical touch and composition behavior still need device verification.
6. LOW, R-03/R-25: complete smallest-phone, large-text, landscape, and measured contrast coverage remains outstanding. Browser layout inspection is not proof of native accessibility compliance.

## Evidence and implemented checks

- Removed the desktop introductory paragraph; centered framebuffer and boot-console container. Reduced trackpad to 44 px high, retaining an accessible target.
- Desktop test verifies tapping the screen focuses the input bridge, typed input reaches the emulator, double tap emits right-click without a delayed left click, and watch mode removes keyboard input.
- Browser test verifies actual per-tab address history, closing tabs, URL rejection and takeover gating.
- Filesystem tests verify actual inode-backed listing metadata, traversal/type checks, 1,000-entry bounds, pre-read 1 MB cap, and binary rejection.
- Files and Code share one mounted editor, preserving unsaved edits across those tabs. Writes and script execution require takeover.
- Timeline records actual phase/checkpoint/console events and bounded captured desktop frames. Historical viewing does not rewind the VM; this is stated in the viewer.
- Separate settings screen uses Hermes-style section/navigation patterns with actual model credential persistence and functional computer navigation. No unsupported settings switches were added.
- Mobile suite: 58 tests passed across 20 files, run serially after concurrent runs exceeded default timeouts. Production build and Capacitor iOS asset sync passed. Host suite: 5 passed.
- Screenshot: ../../output/iphone-concepts/pairing-settings-update.png. This captures the real pairing page, not a generated design image.

These findings record remaining limits. No new audit-driven scope is applied without the user's selection. Already requested UI changes were implemented before this audit.
