# BrowserMesh and KronOS browser and widget swarms

Read-only source review. BrowserMesh checkout a70271ed3abd164b2f2858ce36c8b138a60b4f4a, Apache-2.0. No packages installed, no active browser control, and no timing benchmarks run. Read the KronOS tool workflow and relevant repository guides. Findings below distinguish direct code behavior from runtime risks.

## What BrowserMesh implements

- An explicit sessionId and pageId flow into each operation and come back with operationId. Each session constructs its own serial queue. Cancellation is checked before queued work starts and after an in-flight operation settles. Different sessions have different tails. A request deadline is established before queue admission and checked again at dispatch. Same-session passive waits consume the queue. The action-and-wait path exists for effects triggered by an action in the same session. Tests explicitly cover parallel independent sessions and cancellation before execution. [Runtime](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/runtime/browsermesh-runtime.ts#L934-L967) · [Queue](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/runtime/serial-queue.ts#L3-L33) · [Tests](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/tests/unit/runtime.test.ts#L282-L368)
- A shared Chromium process creates distinct Playwright browser contexts with optional explicit storage-state loading. That isolates cookie/storage state across contexts. The session identifier addresses runtime state and should not serve as a KronOS authorization grant. BrowserMesh is browser execution infrastructure, so the existing MACU worker lease should govern worker authorization. [Context implementation](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/adapters/playwright/playwright-browser-engine.ts#L174-L208) · [License](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/LICENSE)
- Ref actions use page-scoped element handles with expiry and an explicit stale error when a handle is missing, expired, or detached. Main-frame navigation invalidates the map. Retained snapshot cursors are page-scoped and capped at four snapshots with 30-second expiry. Source-node, output byte/character, depth, and ref budgets are explicit. A retained cursor can return historical text while its element handles have since expired or been superseded. Keep observation and actionable generation separate. [Ref resolution](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/adapters/playwright/playwright-browser-engine.ts#L1106-L1138) · [Navigation invalidation](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/adapters/playwright/playwright-browser-engine.ts#L1005-L1011) · [Snapshot bounds](https://github.com/scrollDynasty/BrowserMesh/blob/a70271ed3abd164b2f2858ce36c8b138a60b4f4a/src/domain/snapshots.ts#L6-L20)
- MCP has core/full profiles. Its default structured results also serialize a compatibility text body. Its own README measures roughly 94 KB for full tool discovery on one setup. Treat that as upstream self-report, not local benchmark. Avoid a duplicate browser tool family or repeating structured payloads without client need. ## Local path and improvements

The shared MCP registration in mcp-kron-term/src/index.ts:4402 wraps calls with operation context, scope and route resolution. Standalone uses WshBridge and starts a wsh CLI child per command (mcp-kron-term/src/wsh-bridge.ts:326). Electron's native bridge instead calls routed WSH RPC in-process, verifies tab ownership, and resolves detached HUD routes (emain/kronterm-native-tool-bridge.ts:401–452). Both reach frontend/app/store/tabrpcclient.ts for widget behavior. Native MACU delegation composes client and worker abort signals and tracks unsettled requests (emain/kronterm-tool-server.ts:769; emain/delegation-policy.ts:137).

1. **Fix the sequence failure contract first. Verified code defect.** mcp-kron-term/src/index.ts:2901–2941 appends the per-step string and never checks nested success. The native bridge serializes raw RPC results (emain/kronterm-native-tool-bridge.ts:1297), and the renderer can return success:false without throwing (frontend/app/store/tabrpcclient.ts:785). tool-execution.ts:50–72 only checks top-level result envelopes. A failed native click can therefore be followed by a type or press, then return overall success if focus/snapshot succeeds. The CLI click explicitly maps failure to a nonzero exit (cmd/wsh/cmd/wshcmd-widget.go:427–448), producing parity drift. Normalize native action results before advancing, return structured completed steps and stop index, and cover a false click followed by a dangerous action. Keep post-action observation failure distinct from a failed action so the client does not blindly repeat completed inputs.
2. **Bind workers to exact targets and partition generations. Verified default session sharing by configuration, with collision impact unmeasured.** Widget leases clone the parent context and keep a worker pending set (emain/delegation-policy.ts:98–112,137–151). The native delegation policy allows approved widget types within the tab (emain/kronterm-native-tool-bridge.ts:403–419). Separate blocks alone can still use the same unspecified or named webview partition (frontend/app/view/webview/webview.tsx:113–131,1330–1331,1733–1743). Provision explicit per-worker webview partition only when isolated auth is wanted, bind a MACU capability to workspace/tab/block/guest generation and partition, and revoke on remount/reassignment. Make intentionally shared signed-in state an explicit parent choice. Scoped workers should use the assigned block rather than focused-browser conveniences.
3. **Serialize mutations at a shared target boundary, with an explicit focus resource. Concurrency risk supported by source.** The existing pending set observes promises and provides no FIFO. widget_sequence focuses globally and awaits each action independently (mcp-kron-term/src/index.ts:2885–2941). The renderer can focus a widget and use guest-targeted input, while non-webview paths use window-level input (frontend/app/store/tabrpcclient.ts:687–731,776–797). Queue by canonical widget/page identity and generation at the execution boundary shared by native and CLI; a sequence should hold one lease over its steps. Keep independent guest-targeted pages parallel, serialize actions sharing window focus, preserve user takeover, and revalidate context when work starts. Test same-page overlap, independent pages, cross-transport overlap, and focus stealing. Keep passive waits bounded and offer an atomic listener-before-action operation when an action is expected to trigger the event.
4. **Separate caller timeout from renderer settlement. Verified timeout behavior, potential overlap after timeout.** The native bridge withholds the caller abort signal for tracked writes but still sets the same deadline as the RPC timeout (emain/kronterm-native-tool-bridge.ts:442–447). WSH's timer sends cancel and rejects locally regardless of waitForCancelAck (frontend/app/store/wshrpcutil-base.ts:28–45). Renderer widgetwaitcondition reads the cancellation signal (tabrpcclient.ts:2681–2733), while input handlers may already have dispatched events. Thus the tracked promise can settle before the remote effect is known. Use separate execution acknowledgement and caller response, mark a dispatched mutation uncertain, and hold or fence the resource until the renderer acknowledges settlement or the generation is invalidated. Verify queued cancellation has no side effects and that cancellation mid-drag ends with safe button release.
5. **Make canonical refs opaque and generation-bound. Verified resolution weakness, exploitability and prevalence unmeasured.** Existing browser snapshots generate a per-document random ref prefix, mask DOM password values, and cap candidate scanning (frontend/app/store/browser-observation.ts:8–23,50–55,75–87). They also adopt existing page-controlled data-wave-ref and resolve the first DOM match or fall through to ID/name/aria-label (103–124). A replacement element carrying the same attribute can receive a stale canonical ref, and duplicates are ambiguous. Keep page-owned strings in an explicit locator compatibility path, use a bounded authoritative registry for generated refs, and return STALE_REF for an invalid generation/unknown canonical ref. Unify DOM and accessibility refs under the same target checks.
6. **Trim snapshot work and move deterministic batches down the transport. Verified overhead, speedup unmeasured.** Every widget_snapshot takes a semantic snapshot then an unconditional screenshot in two bridge calls (wsh-bridge.ts:809–812; emain/kronterm-native-tool-bridge.ts:1234–1244), with a CLI spawn per call on standalone. Browser semantics themselves run DOM then AX capture (tabrpcclient.ts:2068–2078). widget_sequence embeds screenshot base64 in its JSON text payload via widgetSnapshot (mcp-kron-term/src/index.ts:2946–2948), unlike widget_snapshot's separate image block (2962–2974). Add opt-in semantic-only observation with count/byte bounds, preserve a backward-compatible visual path and encode visuals as image content. Tag multi-part observations with guest/document generation and detect a change between components. Keep the existing native route and evaluate one bounded renderer batch for the standalone bridge before introducing a persistent transport. Compare baseline to new p50/p95, payload bytes, subprocess/RPC count, timeout and failure codes using the existing diagnostic context (tool-execution.ts:75–108,218–233).

Suggested rollout order is sequence correctness, exact leases and settlement, then lightweight observations/batches. The performance improvements should be measured against same-target serialized operations and independent worker targets. Port these contracts into the existing KronOS tool path. A separate BrowserMesh runtime is useful only if there is a product requirement for standalone headless Chromium sessions, because it would introduce a separate browser state and lifecycle.
