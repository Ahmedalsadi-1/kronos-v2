# 41. Persistence and database migrations

**Priority: P1 - establish a migration and recovery acceptance suite before adding further durable OS state.**

The strongest improvement is to prove upgrade safety against real file-backed SQLite fixtures, including failed upgrades and repeated startup. KronTerm's workspace persistence is central to its product promise; a migration failure can prevent startup even when rendering and agent runtimes remain healthy.

## Observed evidence

`pkg/wstore/wstore_dbsetup.go:28` opens the store and immediately applies embedded migrations. At line 36, migration errors leave initialization unsuccessful. `pkg/util/migrateutil/migrateutil.go:48` reads schema version and rejects a dirty database at line 49; the sampled implementation provides no recovery procedure beyond returning an error. `db/migrations-wstore/000013_os_system_state.up.sql:1` adds durable OS events, capability grants, checkpoints, and expression indexes, so the schema already protects consequential workspace and agent state. No test files were found under `pkg/wstore/`, `pkg/util/migrateutil/`, or `db/` in this scoped review.

The existing WAL configuration and single connection limit (`pkg/wstore/wstore_dbsetup.go:51`, `:55`) are deliberate conservative defaults. Keep these until measured contention justifies a change. Absence of scoped tests is observed; existing application-wide migration coverage or actual production corruption is not established. Dirty-state startup failures after an interrupted or invalid upgrade are a hypothesis requiring fault injection, not a demonstrated user incident.

## Proven repository pattern

Use [pressly/goose's migration execution](https://github.com/pressly/goose/blob/main/migration_sql.go) and [provider acceptance tests](https://github.com/pressly/goose/blob/main/provider_run_test.go) as reference designs for exercising migration behavior and transactional failure paths. Goose explicitly commits migration statements and version bookkeeping together for transactional migrations. Its [MIT license](https://github.com/pressly/goose/blob/main/LICENSE) allows adaptation with attribution if code is copied. The fit is architectural: Go, SQLite, embedded migration inputs, and explicit migration lifecycle tests. This recommendation does not require replacing KronTerm's existing golang-migrate dependency or converting its migration syntax.

## Concrete implementation and gate

Add temporary file-backed SQLite tests that upgrade representative supported schema versions to latest, preserve sample workspace/block JSON and versions, verify OS indexes, reopen successfully, and rerun migration without changes. Inject a failing migration and document whether SQLite state and migration dirty markers agree. Make initialization close newly opened database handles on failure; publish an actionable recovery error while retaining the original database for diagnosis. Never force a dirty schema version automatically.

Release gate: every supported upgrade fixture passes integrity_check, preserves seeded records, reaches expected schema version, and survives two restarts. A failed upgrade must return a precise error, preserve the database, and demonstrate a documented recovery route in a disposable copy. Run targeted Go tests; no go build is needed. Estimate: 2-4 engineering days plus fixture selection.
