# Figma platform audit for KronOS

2026-11-18

**The largest gaps are design-to-live-browser review, named design revisions with review and rollback, and shared design libraries with controlled upgrades.** KronOS already hosts Pen's editable design canvas. The value is in what happens to a design after it is drawn and how it connects to the running app.

## What KronOS already has

- **Editing.** The Pen integration includes the layer tree, property inspector, vector tools, undo, component libraries, animation, and slides. The locally staged Pen schema also documents auto layout, variables and themes, instance overrides, and local library imports. These are existing capabilities at the editor or schema level. Availability through every KronOS UI path was not tested. [Pen host](../../../../../integrations/pen/README.md) · [Staged Pen schema](../../../../../public/pen/skills/pen-schema.md)
- **Live surfaces.** The workspace can put browsers, terminals, and editors on the canvas. Pen's backed frames preserve one canonical owner for each live widget. Workspace canvas has numbered camera bookmarks and task or workflow objects. [Pen host](../../../../../integrations/pen/README.md) · [Workspace canvas](../../../../../frontend/app/tab/workspace-canvas.tsx)
- **Pieces of review.** The browser has local element annotations and research captures. KronRender comparison is designed for generated image variants. Hermes advertises the Figma MCP server in its integration directory. These pieces provide inputs for a design review, while the inspected paths stop short of a persistent Figma-frame-to-implementation review. [Browser annotations](../../../../../frontend/app/view/webview/browser-annotations.ts) · [Research store](../../../../../frontend/app/view/webview/browser-research-store.ts) · [Render comparison](../../../../../frontend/app/view/rendercomparison/render-comparison.tsx) · [Hermes MCP directory](../../../../../frontend/hermes/lib/mcp-directory.ts)

## First three experiments

1. **Design review.** Paste one authorized Figma frame link, capture it with the running checkout page at a fixed viewport, attach one browser annotation, and save the comparison. Reopen and check that both the captured evidence and live targets are still identifiable.
2. **Reviewable design changes.** Save one named Pen revision, have a human or agent change three objects, and present the changes grouped by object. Apply one proposed update and verify that the older snapshot is still inspectable.
3. **Library updates.** Link one Pen component to an implemented component and a design reference. Change the upstream default and confirm that an explicit instance override survives before expanding to a team library.

The fastest directly traceable desktop improvement is **reopen a closed group with its split, order, and last focused view intact**. The strongest canvas/browser opportunity is **the persistent design review**. It combines capabilities already present in KronOS and exposes a clear result a developer can reopen and act on.

## Coverage

- **Answered with static evidence.** Package identity, desktop-shell feature paths, and the presence of separate renderer and local-preview bindings.
- **Compared using published behavior and repository evidence.** Major editor and product families, plus gaps in the inspected Pen host, browser, and canvas entry points.
- **Unresolved.** Authenticated behavior under each Figma plan, vendor backend internals, detailed parity with Pen's shipped drawing and motion engine, and availability of these KronOS paths in a released build.
