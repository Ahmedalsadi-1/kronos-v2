# 36 - ACP approvals and cancellation

Priority: P1. Strongest improvement: make permission resolution an atomic, validated transition shared with the renderer, so a malformed approval cannot discard a pending agent request.

## Observed evidence

Nearest applicable repository instructions were read in `emain/AGENTS.md`; no more specific AGENTS file appeared under the sampled ACP or AI-panel directories. In `emain/acp/acp-agent-manager.ts:771`, `confirmTool` finds a confirmation by call ID, then removes it at line 778 before checking whether the supplied option belongs to that confirmation at lines 780-782. An invalid option therefore returns without sending any response and without retaining the permission for a subsequent valid choice. This is a directly observed control-flow defect; it does not depend on assuming that ordinary UI buttons send invalid IDs. A stale renderer, malformed IPC caller, or future client could trigger it. Runtime occurrence was not reproduced.

The existing positive test at `emain/acp/acp-transport.test.ts:1031` verifies the ACP selected-outcome envelope. Cancellation already settles queued permissions with a cancelled envelope at `emain/acp/acp-agent-manager.ts:801`, and an existing cancellation test begins at `emain/acp/acp-transport.test.ts:1058`. These are useful foundations to extend.

The renderer appends permission cards at `frontend/app/aipanel/use-acp-session.ts:330` and removes them after its own successful approval IPC at line 775. Its sampled status/finish reducer at lines 327 and 345 does not reconcile pending cards when the manager clears permissions. Persisting obsolete cards after cancellation is a hypothesis requiring an integration reproduction; other application event flows were not exhaustively reviewed.

## Proven upstream reference and fit

The official [ACP TypeScript SDK implementation](https://github.com/agentclientprotocol/typescript-sdk/blob/main/src/acp.ts) exposes request/connection abort signals and connection-close cleanup. Its [migration examples](https://github.com/agentclientprotocol/typescript-sdk/blob/main/MIGRATION_0.26_0.27.md) explicitly represent cancelled permission outcomes. The repository is the protocol-maintained TypeScript implementation, making it a directly relevant interoperability reference rather than a popularity proxy. [Apache-2.0 license](https://github.com/agentclientprotocol/typescript-sdk/blob/main/LICENSE) was verified online. Adapt the stable ACP lifecycle contract; do not adopt its explicitly experimental v2 API or wholesale replace KronTerm transport during this fix.

## Implementation and test gate

Validate request identity and option membership before mutation; return a typed rejection for invalid/stale choices. Resolve each permission exactly once, emit its terminal state to the renderer, and reconcile cards on cancellation/disconnection. Gate release on tests proving: invalid option retains a resolvable pending request; repeated clicks produce one response; cancel-versus-approve resolves once; cancellation clears all cards; late tool updates remain accepted; disconnect cannot leave a clickable unresolved card. Run the focused manager/transport tests and renderer reducer tests. No product edits, builds, or tests were performed in this review.
