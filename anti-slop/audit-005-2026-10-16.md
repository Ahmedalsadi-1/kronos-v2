# Browser interaction follow-up

The revision 2 cursor appearance is preserved. No new visual design was introduced.

Browser snapshots now attempt Chromium accessibility roles and computed names, with a DOM/ARIA fallback. Only main-document controls currently become clickable references; iframe and shadow-root targets remain unsupported by this adapter. Password values are omitted. Existing debugger sessions are left untouched.

Browser screenshots use the guest viewport to match browser pointer coordinates. Snapshot failures now surface as errors instead of successful empty results. Drag movement is paced, reports the real path to the cursor overlay, respects the selected button, and releases it on failure. Reference-based drags require both endpoints in the current viewport to avoid scroll-induced coordinate drift.

Validation: focused accessibility, guest IPC, snapshot, viewport capture, observation, drag and native bridge tests passed. The new standalone accessibility and drag modules passed scoped TypeScript validation. Repository-wide typechecking was stopped after seven minutes without a result; no full typecheck success is claimed.

Live limitation: the running native HUD changes selected windows during UI control and reports screenshot unavailable. A successful Hermes action sequence and floating Coucou follow demonstration have not been verified. Dedicated multipoint freehand input is not implemented.
