# 09 - Native bridges

Scope: read-only sample of native/Coucou Swift bridge, Electron companion lifecycle and desktop picker. Read emain/AGENTS.md. No build or execution; recommendations below distinguish observed code from unverified impact.

## P1 - Bound and coalesce native HUD state traffic

Observed: `emain/coucou-hud.ts:185-187` writes every serialized state without checking the writable return value. `native/coucou/kronterm-bridge.swift:113-116` creates a MainActor task for every input line; `:187-188` decodes preview images on that actor. Neither sampled boundary supplies a queue/line-size limit. Hypothesis: a stalled companion or costly preview decoding accumulates buffered frames/tasks and delays user actions.

Recommendation: keep at most the newest pending state snapshot while stdin is backpressured, resume on drain, and limit message/frame bytes. Preserve discrete commands separately. Move expensive image decoding off the UI actor with selection/revision checks before publishing.

Acceptance: a synthetic slow reader receives the latest revision after drain; queued bytes stay bounded; actions remain ordered; stale selection frames never replace current frames; companion exit removes drain listeners. Profile UI responsiveness with deliberately large previews.

Upstream pattern: Node's maintained [stream source documentation](https://github.com/nodejs/node/blob/main/doc/api/stream.md) specifies write-return/drain backpressure and bounded buffering. Its [raw source](https://raw.githubusercontent.com/nodejs/node/main/doc/api/stream.md) was readable and explicitly marks streams Stable, with versioned API history. This API is already in Electron's Node runtime; no dependency adoption needed. Node has an [MIT license plus bundled third-party notices](https://github.com/nodejs/node/blob/main/LICENSE); use the API/pattern rather than importing implementation.

## P2 - Complete picker output on stream close

Observed: `emain/desktop-picker.ts:121-131` collects stdout but resolves on child `exit`. Hypothesis: final stdout can arrive after exit, causing intermittent truncated JSON at `:136`; no reproduced failure. The existing 32 KiB bound and cancellation tracking are useful.

Recommendation: settle once on `close` after streams drain, distinguish timeout/oversize/nonzero exit from cancellation, and retain bounded output. For companion lifecycle, also guard `onExit` against double delivery from error/exit (`emain/coucou-hud.ts:152-159`).

Acceptance: child fixtures emitting split UTF-8/JSON immediately before termination parse successfully; timeout, spawn error and oversized output settle exactly once; cancellation never publishes a late result.

Verified upstream: Node [child-process source documentation](https://github.com/nodejs/node/blob/main/doc/api/child_process.md), [readable raw source](https://raw.githubusercontent.com/nodejs/node/main/doc/api/child_process.md), differentiates exit from close and documents error/exit double handling. Same maintenance/license/fit evidence as above.

Fit caveat: Coucou remains a local personal companion. Its `native/coucou/README.md` explicitly separates MIT code from restricted character/branding/assets; these reliability improvements do not establish redistribution permission.
