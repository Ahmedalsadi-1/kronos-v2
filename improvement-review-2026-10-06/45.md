# 45 - Job processes and PTY lifecycle

Priority: P1 investigation and bounded cancellation fix. Strongest improvement: make terminal input backpressure unable to block job termination or exit-state publication.

## Local evidence

Read `pkg/jobmanager/AGENTS.md`; its referenced `pkg/AGENTS.md` is absent. Sampled job construction, input dispatch, exit handling, and PTY closure. At `pkg/jobmanager/jobcmd.go:180`, `HandleInput` acquires the job mutex and retains it across the PTY write at line 194. `TerminateByClosingPtyMaster` acquires the same mutex at line 221 before closing the descriptor. `waitForProcess` also needs that mutex at line 80 before recording exit state. The input-loop comment at line 179 already identifies the need for a separate synchronized input handler. The manager already serializes its input queue at `pkg/jobmanager/jobmanager.go:96`, so adding another queue without an explicit lifecycle design could duplicate ordering machinery.

Observed: shared state and potentially blocking I/O share a mutex; no write deadline/nonblocking setup appears in this package. Hypothesis: a child that stops reading input can stall a sufficiently large paste, and attempts to close the PTY or report process exit can wait behind that write. This was not reproduced in this read-only review; treat it as a credible failure mode, not a confirmed production incident.

## Proven repository pattern and fit

[creack/pty's maintained Unix PTY examples](https://github.com/creack/pty/blob/master/README.md) separate input/output copying and explicitly arrange descriptor cleanup. Their documentation also says the examples are demonstrations, so copying them wholesale is inappropriate. The useful pattern is ownership of descriptor lifetime independently of blocking input. Its [license](https://github.com/creack/pty/blob/master/LICENSE) is MIT and requires preservation of notices if substantial code is copied. Prefer adapting lifecycle principles with local code rather than introducing a second PTY dependency.

Important compatibility caveat: `go.mod` declares creack/pty but replaces it with `github.com/photostorm/pty` at commit `31354506054b`. Audit that fork's `pty.Pty` close/write behavior before choosing cancellation mechanics; upstream examples alone do not establish behavior of the actual dependency.

## Plan and acceptance gate

First reproduce with a real PTY child that deliberately stops reading and enough input to exhaust buffering. Then move descriptor writes outside the state mutex, preserving ordered input, stable ownership, and idempotent close. Give termination a path that can interrupt pending writes; document platform limitations and handle partial writes. Keep signal and resize responsiveness explicit rather than forcing them behind unlimited input.

Gate: targeted Darwin and Linux integration tests prove close finishes within a bounded deadline while input is blocked, exit information remains available, ordinary typing/paste order is preserved, and concurrent close/resize produces neither races nor descriptor leaks. Run targeted `go test -race` where supported; never `go build`. No product code changed or builds executed during this review.
