# 35. Agent selection context: validate and budget the final attachment

**Priority: P1.** Introduce a shared runtime schema and total UTF-8 byte budget immediately before selected browser or desktop context enters Hermes. Keep the existing user review flow. This is a bounded improvement to context reliability and disclosure control, not a recommendation to replace the agent engine.

## Local evidence

`frontend/app/view/hermes/selection-context.ts:4-10` limits only the comment to 2,000 JavaScript characters. It serializes all other payload fields, removing only the top-level screenshot. Object spread/rest also preserves unexpected runtime properties despite the TypeScript declarations. `frontend/app/workspace/kronterm-hud-controls.tsx:19-25` passes that serialized string directly to `sendHermesContext` after the user supplies a comment. `frontend/types/desktop-grab.ts:1-10` describes strings and numeric bounds but does not enforce sizes or finite coordinates at runtime. Existing coverage in `frontend/app/view/hermes/selection-context.test.ts:5-35` verifies screenshot omission and comment truncation, but not oversized selections, malformed values, unknown properties, or total payload size. Browser extraction already has field budgets in `frontend/types/browser-grab.ts`; the final serializer should reuse those rather than invent conflicting limits.

**Observed:** these serializers have no runtime allowlist or total-byte check. **Unverified:** upstream desktop extraction or IPC might enforce additional limits; no production leak, crash, latency regression, or successful prompt injection was reproduced. JSON formatting and the revalidation sentence do not themselves establish an execution security boundary.

## Proven pattern and fit

Use the established [colinhacks/zod repository](https://github.com/colinhacks/zod) pattern: parse unknown input into a validated object before consuming it. Its [string validation tests](https://github.com/colinhacks/zod/blob/main/packages/zod/src/v4/classic/tests/string.test.ts) exercise minimum/maximum lengths, invalid types, and boundary cases through `safeParse`. Transfer those boundary assertions to selection fields and add an application-specific UTF-8 budget after serialization. Zod is already declared in `package.json:209` (`^4.4.3`), so this need not add a dependency or framework. [MIT licensing](https://github.com/colinhacks/zod/blob/main/LICENSE) permits reuse subject to retaining its notice when copying substantial source. Source pages were checked online on October 6, 2026; pin a release or commit before copying code.

## Implementation and acceptance gate

Define curated browser and desktop context schemas, strip unknown keys, reject invalid coordinates, and truncate approved text fields with explicit omission metadata. Keep source identity, bounds, selector, and capture provenance ahead of descriptive text when trimming. Use one proposed 32 KiB UTF-8 attachment ceiling, subject to actual provider limits. Do not interpret selected text as user authorization.

Ship only when tests show oversized Unicode payloads remain within the byte ceiling; unknown nested image/secret properties never enter output; malformed coordinates fail clearly; ordinary selection identity survives trimming; existing screenshot/comment cases still pass; and the HUD preserves the reviewed selection with a useful error when validation rejects it. No product files changed or builds run during this review.
