# 23 - SSH handshake cancellation

**Priority: P1 reliability candidate.** Sampled the direct and ProxyJump transport-to-handshake path in `pkg/remote/sshclient.go`, after reading `pkg/remote/AGENTS.md`. No product files were changed and no build or tests were run.

## Observed evidence

At `/Users/albsheralsadi/kronterm/pkg/remote/sshclient.go:847`, TCP establishment uses `net.Dialer.DialContext`; the ProxyJump branch uses `currentClient.DialContext` at line 855. Both then call `ssh.NewClientConn` synchronously at line 862. There is no connection deadline or cancellation callback between establishment and negotiation. The client configuration at lines 833-838 also leaves `Timeout` unset, although setting that field alone would not solve this handshake problem.

The verified [golang/crypto SSH client source](https://github.com/golang/crypto/blob/master/ssh/client.go) shows that `NewClientConn` performs the handshake synchronously and closes the supplied connection on handshake failure. Its `ClientConfig.Timeout` field concerns TCP establishment; it does not provide a context argument to `NewClientConn`. This supports a bounded finding: cancellation supplied to KronTerm's dial step does not, by itself, interrupt the subsequent SSH negotiation.

## Hypothesis and proposed improvement

A TCP peer that accepts the connection but stalls its SSH identification or handshake can leave a connection attempt waiting after its context is canceled. This is source-backed inference, not a reproduced hang or proof of a production incident. Bind cancellation to closure of the newly opened transport while negotiation runs, then remove that binding before returning a successful client. Consider a handshake deadline separately, with explicit allowance for the existing interactive authentication and host-key prompts. Avoid closing the existing ProxyJump parent client when canceling only its child transport.

## Acceptance criteria and test gate

Add a deterministic local listener test that accepts TCP and sends no SSH banner; cancel the attempt context after accept and require prompt return. Cover an expired deadline and a stalled transport opened through a test SSH jump server. Verify successful negotiation remains usable after the connection-attempt context is canceled, and preserve interactive prompts within their existing time budgets. Run `go test ./pkg/remote/...` and repeat the focused cancellation tests with the race detector. These are proposed gates, not completed validation.

## Upstream fit and maintenance

`go.mod:34` already adopts `golang.org/x/crypto v0.49.0`; reuse that maintained Go-project dependency instead of introducing another SSH implementation. The reviewed upstream master source is a behavioral reference, so check the pinned version when implementing. Its [BSD three-clause license](https://github.com/golang/crypto/blob/master/LICENSE) fits redistribution with retained notices. The smallest local lifecycle fix avoids a fork and keeps future crypto updates straightforward.
