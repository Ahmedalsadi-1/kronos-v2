# KronTerm improvement plan

Date: 2026-10-06. Completed 50-section review and prioritized implementation plan.

## Objective and method

Make existing KronTerm journeys dependable: launch, restore, terminal/SSH, workspace switching, agent execution and cancellation, browser/computer-use, and quit/update. Recommendations cover 50 sections: 48 distinct subagent reviews and two direct primary-agent reviews, following the user's request to finish with fewer agents. Reviewers inspected local code and used established online primary repositories, with inherited verification explicitly noted where fresh browsing failed. Reports are scoped samples, not exhaustive security or quality audits. The current worktree contains substantial changes; reviews describe that state, not a clean release tag. Only review artifacts are added.

Prioritize verified source-level problems with broad user impact, then lifecycle and data-integrity gaps, then measured performance and interaction quality. Distinguish source observations from runtime hypotheses. Source-level tests or small local language checks establish a mechanism; they do not establish production frequency or remote exploitability.

## Delivery order

| Order | Outcome | Initial scope | Completion gate |
| --- | --- | --- | --- |
| 1 | Privileged operations stay within their approved caller and backend | Resolved URL origin validation, IPC sender/frame/role checks, browser permission/session policy | Invalid origins and callers cause zero privileged side effects; legitimate surfaces remain functional |
| 2 | Workspace commands cannot disappear and failures cannot strand startup | Mutation queue, bounded startup handshake, awaited idempotent shutdown | Slow/failing RPC and rapid command fixtures preserve all mutations; failed startup exposes recovery; quit drains or times out explicitly |
| 3 | Agent transport and supervision survive malformed streams and failed processes | UTF-8 framing, frame limits, process error/readiness/exit handling, bounded retry policy, MCP session ownership | Every-byte-split Unicode fixture passes; process failures settle once; retry/session/buffer resources remain bounded |
| 4 | Release verification is executable | PR tests/typecheck, build-output budget, contract checks, deterministic desktop smoke | A deliberately broken check blocks the relevant gate; packaged clean-install and upgrade smoke pass |
| 5 | Workspace, terminal, files, editor and agent flows retain coherent state | Hydration, PTY/LSP results, focus, preview/browser recovery and live ownership | Domain-specific acceptance criteria and cross-presentation restore/focus checks pass |
| 6 | Performance improves against a recorded baseline | Startup spans, queues/buffers, terminal throughput, canvas/chat scale | Before/after p50/p95 and memory figures on fixed workloads, with no correctness regression |

These are proposed implementation workstreams, not changes already performed. Narrow security/correctness fixes should be separate reviewable PRs. Introduce instrumentation and release gates alongside them; do not wait for a large rewrite.

## First implementation slices

### A. Restrict backend API destinations and privileged IPC

Observed API origin escape: `emain/kronoscode-runtime.ts:595-613` checks raw path prefixes, resolves the path and attaches Basic credentials without comparing the resolved origin. A local URL-only check confirms an accepted slash-backslash path changes host. Do not infer that remote content can already invoke this method. Compare final origin before adding credentials, define redirect behavior and test hostile path variants with a fixture server that receives no credentials.

IPC authorization is inconsistent: `emain/emain-ipc.ts:503-504` returns arbitrary requested environment keys; agent proxy handlers at `:1100-1101` and `:1119-1120` ignore sender identity. Extend existing registered-sender policy from `emain/native-hud-ipc.ts` into narrow channel registration with frame, surface role and payload validation. Inventory legitimate capabilities for ordinary renderer, pet, overlay, HUD and browser guest before migration. Preserve public method and compatibility names.

Reference: [Electron security guidance in its repository](https://github.com/electron/electron/blob/main/docs/tutorial/security.md). Local evidence: [03](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/03.md), [04](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/04.md), [05](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/05.md), [verification](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/root-verification.md).

### B. Preserve window mutations and make lifecycle settlement explicit

`emain/emain-window.ts:534-536` overwrites pending create/close actions as well as navigation. Use FIFO commands for mutations and explicit coalescing only for navigation, with a completion/cancellation result per caller. Make disposal independent of backend persistence policy, and cancel delayed callbacks when owners close.

At startup, a spawn failure rejects a separate promise while readiness can remain unresolved (`emain/emain-wavesrv.ts:39-44,95-97`; `emain/emain.ts:448-454`). Replace fixed-delay readiness assumptions with a bounded handshake and a recoverable failure view. Quit should await one shared cleanup barrier with an explicit deadline.

References: [VS Code queues](https://github.com/microsoft/vscode/blob/main/src/vs/base/common/async.ts), [disposal](https://github.com/microsoft/vscode/blob/main/src/vs/base/common/lifecycle.ts), [shutdown lifecycle](https://github.com/microsoft/vscode/blob/main/src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts). Implement small local equivalents rather than adopting VS Code's service container. Local evidence: [01](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/01.md), [02](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/02.md).

### C. Make agent streams and processes bounded and lossless

ACP decodes each raw chunk before frame assembly (`emain/acp/acp-transport.ts:187-194`). Use stateful decoding or byte framing and bound unfinished frames. Test Arabic, CJK and emoji at every byte boundary, not only ordinary one-chunk JSON.

Make process startup observe error/exit through readiness and health checks; settle each generation once. Cap retries for broken installations, expose degraded/repair status and allow explicit retry. Bound MCP sessions, create them only for valid initialization, dispose them with the caller and catch failures at the HTTP boundary. Keep state snapshots coalescible and commands lossless across native bridge backpressure.

References: [VS Code language-server JSON-RPC reader](https://github.com/microsoft/vscode-languageserver-node/blob/main/jsonrpc/src/common/messageReader.ts), [Execa process settlement](https://github.com/sindresorhus/execa/blob/main/lib/resolve/wait-subprocess.js), [official MCP v1 server example](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.x/src/examples/server/simpleStreamableHttp.ts), [Node stream contract](https://github.com/nodejs/node/blob/main/doc/api/stream.md). Adapt principles to ACP NDJSON and the installed SDK version. Local evidence: [06](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/06.md), [07](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/07.md), [08](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/08.md), [09](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/09.md).

## Upstream adoption rules

For every proposed reuse, record the exact upstream commit, source path, behavior being borrowed, license/notice obligations, and the matching KronTerm test. Repository popularity alone is not evidence of correctness. Prefer existing dependencies and narrow designs that match Electron + Go + React. Do not import an entire upstream editor or orchestration platform for a small lifecycle fix.

Main-branch links in review reports are discovery references. Pin commits at implementation time; verify installed-version compatibility and supported release lines. Evaluate new runtime dependencies in a small spike with bundle/startup impact, maintenance and rollback checks. Copyleft examples may inform an independently written policy, but are not approved for code copying. Native companion assets and Labs functionality require separate product/release decisions.

## Verification and rollback

For implementation, use existing Vitest, Go package tests and MCP/mobile suites where relevant, followed by focused packaged desktop smoke. No Go build commands are proposed. Preserve legacy Wave identifiers and generated bindings; change generator sources and regenerate where needed. Do not edit embedded sibling repositories as part of core improvements.

Each slice needs a reproducer or measurable baseline, one bounded change, acceptance criteria, domain tests and a rollback path. Permission/profile migrations need reversible data migration; contract changes need compatibility checks; performance changes need a before/after workload. Do not promise speed gains or reduced incidents until measured.

## Terminal, editor, browser and sandbox candidates

- **P1: One stable process-completion result** ([22](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/22.md)). Pointer/shared completion ownership must survive every constructor and interface assignment. Repeated and concurrent waiters must observe the same nonzero exit and SSH signal; successful remote completion must be zero. Owner: Go terminal maintainer. Reference: [Go exec state ownership](https://github.com/golang/go/blob/master/src/os/exec/exec.go).
- **P1: Byte-correct language-server framing** ([25](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/25.md)). Use the existing byte parser or a compatible maintained JSON-RPC reader; do not slice decoded strings by byte Content-Length. Owner: Electron/LSP maintainer. Gate: two Unicode responses at every byte split and proper cleanup. Shares test principles with ACP but keeps distinct framing protocols.
- **P1: Sandbox instance ownership** ([29](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/29.md)). Reserve starts atomically; bind cancellation and completion to an immutable session generation. An old callback must never alter a new same-name session. Owner: Go sandbox maintainer. Gate: barrier-controlled start/stop/restart and race-enabled package tests. [Coder agent lifecycle](https://github.com/coder/coder/blob/main/agent/agent.go) is an AGPL design reference; implement independently or obtain license clearance before source copying.
- **P1 reliability candidate: Cancel SSH handshake** ([23](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/23.md)). Bind attempt cancellation to the new transport only during negotiation; detach it on success and preserve prompt budgets. Owner: remote maintainer. Gate: no-banner listener and jump-host fixtures. Reference: [Go crypto client](https://github.com/golang/crypto/blob/master/ssh/client.go).
- **P2: Preserve binary terminal input** ([21](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/21.md)). Wire the existing xterm `onBinary` API with byte-preserving encoding and disposal, independently of Unicode text. Gate: bytes 0x80/0xff arrive unchanged and a real mouse-report fixture. Reference: [xterm 5.5 API](https://github.com/xtermjs/xterm.js/blob/5.5.0/typings/xterm.d.ts).
- **P2: Media and browser recovery semantics** ([26](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/26.md), [27](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/27.md)). Gate on same-path replacement plus failed iframe/navigation event sequences.
- **P2: Live computer-use registration** ([28](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/28.md)). Prune deleted blocks while retaining pending-creation ownership. Gate on close/recreate without duplicate streams and correct explicit target routing.
- **P2 measurement candidate: Virtualize large directories** ([24](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/24.md)). Use existing TanStack Virtual only after profiling; preserve keyboard access to unmounted rows, drag targets and menu identity. Gate: bounded mounts for 10,000 entries and before/after browser measurements. Reference: [official virtualizer API](https://github.com/TanStack/virtual/blob/main/docs/api/virtualizer.md).
- **P2: Bound state retention and styling** ([17](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/17.md), [18](/Users/albsheralsadi/kronterm/improvement-review-2026-10-06/18.md)). ## Milestones and success measures

1. **Boundary and correctness baseline:** packages1–4 plus initial CI; rejected requests have no side effects, commands/permissions settle, Unicode is lossless.
2. **Lifecycle and durable-state baseline:** packages5–10; no old callback mutates replacement state, abandoned streams/children settle, supported database upgrades and released RPC payloads pass.
3. **Interaction and scale baseline:** packages11–13; keyboard and recovery journeys pass, caches/queues track live resources, fixed large-workload measurements establish justified optimization targets.
4. **Product and optional-service handoff:** packages14–16; Labs/voice pass explicit failure/device tests, public instructions match the distributed product, provenance is reviewable.

Record cold/warm startup p50/p95, queue depth/high-water marks, open session/child/cache counts after repeated lifecycle loops, fixture stream fidelity, packaged smoke failure rate, and supported-upgrade pass rate. Keep content, secrets, raw transcripts and screenshots out of default metrics. Start with local redacted diagnostics; remote telemetry needs a separate product/privacy decision. [OpenTelemetry JS](https://github.com/open-telemetry/opentelemetry-js), verified during synthesis, is a candidate only if existing instrumentation cannot supply the required correlation; no telemetry dependency or collection is enabled by this review.
