# 38 - Optional voice capture and audio bridge

Priority: P1 before expanding voice availability. Scope sampled: `audio-engine/audio_capture.py`, `audio-engine/main.py`, `audio-engine/stt_engine.py`, and `emain/emain-audio.ts`; read `emain/AGENTS.md`. This is a static review, not a microphone reproduction or full voice audit.

## Strongest improvement

Make capture a bounded, loss-aware utterance producer with explicit segmentation and lifecycle states. At `audio-engine/audio_capture.py:136`, energy detection uses a fixed RMS threshold; enabling VAD instead reaches an unconditional `True` at line 142. Consequently that enabled code path cannot detect silence or finish an utterance normally. This is directly observed code behavior; whether users can currently enable it through UI is unverified. The growing speech deque at lines 120/124 has no duration ceiling, so continuous input can accumulate indefinitely. Default capture uses energy mode, which can also remain active under sustained noise; its actual frequency in real environments is a hypothesis.

At lines 78-86, the consumer clears the shared result and event before waiting. A completion delivered while STT is busy can therefore be erased by the next read. Preserve completions in a bounded queue, define overflow behavior, and move assembly/VAD work out of the realtime callback where practical. Preserve approximately 300ms of leading frames, enforce a maximum segment duration, and reset/wake readers on stop. The existing code discards pre-speech history at lines 118-119.

## Verified upstream fit

Use the segmentation pattern in [wiseman/py-webrtcvad example.py](https://raw.githubusercontent.com/wiseman/py-webrtcvad/master/example.py): bounded pre-roll, separate triggered/untriggered states, and voiced/unvoiced window thresholds. Its 16kHz mono 16-bit PCM example fits KronTerm's existing capture format. Treat its offline collector as an algorithm reference, not a realtime callback implementation, and do not copy its stdout diagnostics into the JSON protocol. [The upstream license](https://github.com/wiseman/py-webrtcvad/blob/master/LICENSE) identifies MIT for the wrapper and BSD-style terms for bundled WebRTC code; retain both notices if distributed. Packaging/native wheel compatibility still needs validation. These sources were retrieved online; no claim of current maintenance or universal noise performance is implied.

## Plan and test gate

First implement a deterministic frame/segment state machine with a bounded completion queue. Then evaluate real VAD against the current energy baseline using consented fixture audio. Gate rollout on tests for silence, short speech with preserved onset, back-to-back utterances during slow transcription, prolonged noise with a memory bound, and stop/restart with no stale audio. Verify model-load failure keeps listening false: `main.py` currently sets STT ready after an empty transcription call while `stt_engine.py` returns before loading for empty input. Separately test the Electron bridge with JSON records split across stdout chunks; `emain/emain-audio.ts` currently parses each chunk independently. Acceptance is correct lifecycle and complete transcripts under those fixtures, followed by macOS microphone permission/device failure checks.
