## Priority P2: Remove stale app-to-block registrations

Observed: `/Users/albsheralsadi/kronterm/frontend/app/view/appstream/computer-use-stream-manager.tsx:24` reconciles by adding current models to a persistent map, but never clears entries for removed models. At line 63, any cached entry causes focus and an early return, suppressing creation. At line 47, cached identity also wins over an explicit activity block ID. A closed app-stream block can therefore remain the lookup result indefinitely while this manager stays mounted. The map has no deletion anywhere in the sampled component.

Hypothesis requiring runtime reproduction: create a desktop activity for an app, close its generated stream block, then emit another activity for the same app. The old ID is focused and a replacement stream is never created. Exact visible behavior depends on `refocusNode` handling a removed block and the manager's mount lifetime. This is a source-supported lifecycle defect, not a demonstrated production incident.

Recommendation: validate cached IDs against the current model registry, prune absent entries, and rebuild registrations from live models. Account for the short interval between asynchronous creation and registry mounting so pruning does not create duplicate blocks. Only prefer an app-name match over explicit activity identity when that match remains live.

Acceptance criteria: closing a stream then receiving the same app activity creates exactly one replacement; repeated activity while creation is pending creates no duplicate; valid existing streams are focused; controls with stale cache and a live explicit block ID reach the live model. Include manager unmount/remount in the regression gate.
