# 22 - PTY process completion

## Priority: P1 - Persist the result shared by all waiters

Read-only sample: `pkg/shellexec/conninterface.go` and the terminal lifecycle in `pkg/blockcontroller/shellcontroller.go`. The repository root AGENTS.md applies; neither sampled directory has a nearer AGENTS.md. No product edits, builds, or tests were performed.

**Observed:** `CmdWrap.Wait` at `pkg/shellexec/conninterface.go:57` uses a value receiver. Its shared `*sync.Once` prevents repeated underlying waits, but the callback assigns `WaitErr` to the receiver copy. The original wrapper retains nil. Subsequent callers therefore return nil even when the first waiter received a nonzero-exit error. `SessionWrap.Wait` at line 193 repeats this pattern; its `ExitCode` at line 172 and `ExitSignal` at line 180 read the original, unchanged result. This is a source-level correctness defect, not merely a possible race.

Multiple waiters are present: controller output cleanup at `pkg/blockcontroller/shellcontroller.go:541`, the controller completion goroutine at line 601, and `ShellProc.Close` at `pkg/shellexec/shellexec.go:63`. Consequently, whichever caller wins the once can affect the error published through `SetWaitErrorAndSignalDone`. Local `CmdWrap.ExitCode` reads `exec.Cmd.ProcessState`, so this review does not claim that every local displayed exit code is wrong. Remote session status loss follows from the stored-error accessor, although an end-to-end SSH reproduction remains unperformed.

**Recommendation:** Give each wrapper one stable shared completion record, using pointer receivers and pointer-returning constructors or an explicit shared state object. Ensure all constructors and interface assignments preserve that identity. Normalize successful SSH completion to exit code zero rather than the current nil-to-minus-one path. Keep underlying Wait execution single-owner and make all readers wait for completion before accessing mutable outcome state.

## Acceptance and test gate

- Sequential and concurrent Wait callers receive the same nonzero error; the underlying process is reaped once.
- SSH success returns zero; SSH nonzero exit and signal remain visible after repeated waits.
- Controller completion and cleanup ordering cannot turn failure into success.
- Add focused wrapper tests and run `go test -race ./pkg/shellexec ./pkg/blockcontroller`; include a real local PTY and SSH fixture where supported. No `go build` gate.

## Upstream and adoption

[Go's exec implementation](https://github.com/golang/go/blob/master/src/os/exec/exec.go) is the established primary reference: it stores process completion on pointer-owned Cmd state and reports unsuccessful exits. Adopt that ownership principle locally; no new dependency is required. Go uses a [BSD-style license](https://github.com/golang/go/blob/master/LICENSE); reference rather than copying implementation keeps maintenance small.

[creack/pty](https://github.com/creack/pty), under [MIT](https://github.com/creack/pty/blob/master/LICENSE), fits Unix PTY mechanics, but `go.mod:92` replaces it with a photostorm fork. Do not assume upstream examples describe KronTerm's Windows implementation or remove the replacement during this fix.
