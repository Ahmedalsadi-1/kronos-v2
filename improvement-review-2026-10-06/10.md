# 10 - Pet and overlays

## P1: Unauthenticated activity ingress permits forged agent status

Observed: `/Users/albsheralsadi/kronterm/emain/emain-pet.ts:281` starts an HTTP server with wildcard CORS. Lines 285-307 accept POST JSON and immediately dispatch pet notifications or activity. Line 318 binds predictable loopback port 4097. This handler has no token, origin validation, or runtime schema gate. `/Users/albsheralsadi/kronterm/frontend/pet/pet.ts:456` assigns incoming preview URLs to an image source. BrowserWindow isolation and sandboxing are correctly enabled at emain-pet.ts:340.

Hypothesis: Unrelated local processes can forge success/approval states, agent activity, and preview URLs. Browser access depends on local-network protections; no browser exploit was exercised. This is an integrity issue, not demonstrated code execution.

Recommendation 1: Require a per-launch opaque token provisioned only to authorized producers; reject invalid credentials before parsing. Restrict allowed browser origins. Transfer the mandatory token boundary from [VS Code serverConnectionToken.ts](https://github.com/microsoft/vscode/blob/main/src/vs/server/node/serverConnectionToken.ts), which validates supplied connection tokens and supports controlled provisioning. Do not copy optional unauthenticated mode or URL token conventions.

Acceptance: Missing/wrong-token POSTs return 401/403 without state changes; authorized producers continue working; disallowed origins receive no CORS grant; tokens rotate on restart and never enter logs.

Recommendation 2 (P2): Enforce a byte-count limit and schema before dispatch. emain-pet.ts:296 checks prior string length, allowing an oversized first chunk and silently discarding subsequent chunks. Return 413 immediately on overflow; validate kinds, enums, coordinates, text lengths, and preview URL schemes.

Acceptance: Oversized single and multiple chunks both return 413; malformed variants return 400; rejected requests never alter pet/overlay state or broadcast activity; bounded valid events pass.

Upstream evidence: VS Code is a Microsoft-maintained established editor. The verified main-tree source exists in a repository listing approximately 43.8k forks and an active issue/PR queue. This supports adoption and ongoing activity, not a security guarantee. Its [MIT license](https://github.com/microsoft/vscode/blob/main/LICENSE.txt) permits copying with notices. Adapt the small authentication pattern without importing the entire server subsystem. Electron's [security guide](https://github.com/electron/electron/blob/main/docs/tutorial/security.md) supports narrowly granting capabilities to untrusted content.
