## P2: Close the native runtime when the MCP input pipe ends

Observed: `/Users/albsheralsadi/kronterm/mcp-kron-term/src/index.ts:4399` creates the stdio transport and registers cleanup only for process exit, SIGINT, and SIGTERM (4401-4408). There is no stdin `end` cleanup or server-close cleanup here. The installed SDK is 1.29.0; its stdio implementation subscribes only to stdin data and errors, so EOF does not itself call transport.close(). `/Users/albsheralsadi/kronterm/mcp-kron-term/src/kron-computer-use.ts:113` starts a native child with three pipes; line 87 provides explicit child termination and pending-request rejection.

Hypothesis: after a computer-use call starts this child, an MCP client that closes stdin without delivering a signal can leave the server and native child alive. The referenced child/pipes can keep Node running, preventing the process-exit cleanup from executing. This is a concrete missing lifecycle route; an actual leak has not been reproduced during this review. A client that reliably escalates to SIGTERM may hide it, so do not claim all clients leak.

Recommendation: create one idempotent shutdown routine that closes the MCP server and native bridge, and invoke it on input EOF and signals. Preserve SDK-owned transport callbacks rather than overwriting them. Make cleanup bounded and remove registered process listeners when teardown completes. Keep diagnostics on stderr and protocol messages exclusively on stdout.

Acceptance criteria/test gate: a child-process integration test initializes the MCP connection, starts a fake persistent native runtime, closes client stdin, and verifies both processes terminate within a bounded deadline without SIGTERM from the test. Separate cases cover SIGTERM, duplicate shutdown, and EOF during an active request. Assert stdout remains valid MCP JSON-RPC. Run the existing package test command only in the later implementation task; no test pass is claimed here.
