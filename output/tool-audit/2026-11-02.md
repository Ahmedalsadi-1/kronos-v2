# Tool audit, November 2, 2026

## Evidence and scope

The supplied live report covers 49 unique tools out of 234 registered tools.
Its 43 clean passes describe that sample only. Expected permission denials and
invalid arguments should be separated from implementation failures in future runs.
This follow-up uses source inspection and automated tests. No live KronTerm MCP
connection is exposed in this chat, so these results do not establish live tool coverage.

## Findings

- Native background launch: confirmed that window inventory or enrollment could
  throw after a successful app launch. Fixed the response to preserve app identity,
  explicitly report `launched: true`, `windowsVerified: false`, pause the workspace,
  and instruct the caller not to retry. Ownership and window checks remain enforced.
- Delegated VM widget access: the native bridge deliberately excludes VM widgets
  from the widget-only scope. A worker must receive sandbox authority through the
  sandbox delegation route; relaxing the widget allowlist would broaden authority.
  The reported workflow mismatch remains unresolved.
- Linux reservation failures: generation and assignment checks are intentional.
  Listing or displaying a VM does not authorize an agent to control it.
- Device boot timeout followed by a running device: requires reconciliation before
  retry. Not reproduced in this follow-up.
- Productivity invalid discriminator/ID: supplied report indicates successful
  operation with the live schema. This alone does not establish a backend defect.
- ACP startup/authentication failures: not reproduced; runtime and authentication
  prerequisites remain distinct from tool correctness.

## Validation

The full MCP build and test suite passed: 160 tests, zero failures. This includes
native ownership, background displays, Linux reservations, tool discovery,
productivity, widget snapshots, and a new post-launch inventory-failure regression.

## Desktop direction

The active backend is QEMU Ubuntu with XFCE, two virtual CPUs and 2 GB RAM.
The upstream container provider is retained source, not the current runtime.
The requested direction is a KronTerm-owned, lightweight single-app desktop.
The guest session must change as well as its viewer: removing viewer chrome alone
does not remove XFCE services. Desktop implementation and visual validation remain
pending; no desktop behavior changes are included in this audit fix.
