# 34/50 - Hermes plugin transport boundary

**Priority: P1 hardening, pending reproduction.** Reject HTTP redirects in the authenticated Python tool bridge and define its permitted destination explicitly. This is a small adapter change with a meaningful credential boundary; it does not require replacing Hermes or introducing an asynchronous HTTP stack.

## Local evidence

The nearest applicable instructions are the root `AGENTS.md`; no closer agent instructions were found under `agents/hermes`. The focused path is `agents/hermes/plugins/kronterm-tools/__init__.py:42`: `_bridge_request` reads the bridge URL and bearer token from environment variables, checks only that they are present (lines 43-46), puts Authorization into ordinary request headers (lines 47-51), and invokes the default `urllib.request.urlopen` at line 65. No explicit redirect handler or destination allowlist appears in that path. Existing tests at `agents/hermes/tests/test_kronterm_tools.py:78` mock `urlopen` to verify HTTP error normalization; the socket-budget test at line 127 also substitutes a response object. These are useful unit tests, but they cannot exercise real HTTP redirect behavior.

**Observed:** the adapter delegates redirect policy to the default opener while attaching a bearer credential. **Unverified:** an actual credential leak, redirect from the production bridge, or attacker control of the injected URL. The desktop runtime may already strictly own URL generation. Verify that runtime boundary before presenting this as an exploitable vulnerability.

## Established repository pattern

[aio-libs/aiohttp](https://github.com/aio-libs/aiohttp) explicitly compares redirect origins and removes Authorization, Cookie, and Proxy-Authorization on an origin change in [its client implementation](https://github.com/aio-libs/aiohttp/blob/master/aiohttp/client.py). The browsed source placed that check at lines 831-835. This is the transferable principle: credentials belong to an origin and redirect handling must deliberately enforce that relationship. The [Apache-2.0 license](https://github.com/aio-libs/aiohttp/blob/master/LICENSE.txt) was verified. Adopt the principle and a regression-test shape, rather than adding aiohttp solely for this synchronous plugin. Upstream master links are moving references; pin the selected upstream revision during implementation.

## Concrete plan and acceptance gate

Use a dedicated urllib opener that refuses redirects for the local RPC endpoint. Confirm supported endpoint shapes with the desktop launcher; reject unexpected schemes, credentials in URLs, and remote hosts only if the launcher contract guarantees loopback. Add a two-server integration fixture: authenticated requests hit server A; A redirects to server B on another port. For 301/302/303/307/308, B must receive zero requests, the adapter must return a clear bridge error, and no credential appears in that error. A direct successful response must still work. Preserve existing timeout, bounded-output, and no automatic side-effect replay behavior. Acceptance requires these tests plus the existing Python adapter suite; no product code changes or tests were run during this review.
