# 20 - Command center keyboard navigation

Priority: P2. Keep the keyboard-selected command visible in the scrolling results pane. This is a focused interaction correction; replacing the palette or its search algorithm is unnecessary.

## Local evidence

At `frontend/app/modals/command-palette.tsx:171`, ArrowDown prevents the browser default and changes only `selectedIndex`; ArrowUp does the same at line 176. The input retains focus. Selection is rendered through `aria-selected` and `data-selected` at lines 234-235, with no selected-element ref, scroll call, or selection visibility effect anywhere in this component. Meanwhile, `frontend/app/modals/command-palette.scss:77` caps results height and enables vertical scrolling. Rows have a 54px minimum height at line 98. The six built-in applications plus two commands already exceed a 440px results region once group headings and padding are included; installed applications and workspaces extend it further.

Observed in source: arrow navigation updates the selected row without moving DOM focus or explicitly scrolling the list. The code therefore permits selection beyond the visible results window. User impact is a source-backed inference, not a runtime observation: a keyboard user can press Enter on an unseen command, and ArrowUp from the initial row wraps directly to an unseen last row. No application was launched or test run for this review. Existing `command-palette-utils.test.ts` covers matching and ranking, not scrolling or navigation.

## Verified upstream and adoption

The primary [cmdk implementation](https://github.com/dip/cmdk/blob/main/cmdk/src/index.tsx) implements `scrollSelectedIntoView()`, finds the selected item using `aria-selected`, and calls `scrollIntoView({ block: 'nearest' })`; it also accommodates group headings. This is a directly applicable implementation pattern verified on 2026-10-06. The old pacocoursey repository URL currently redirects to dip/cmdk. Adopt the behavior in a small local selection effect or helper, using the existing list/item IDs, rather than adding a command-menu dependency solely for scrolling. This preserves KronTerm's custom actions and presentation with a small maintenance surface.

The [upstream license](https://github.com/dip/cmdk/blob/main/LICENSE.md) is MIT; retain its notice if copying substantial source. An independently written use of the browser scrolling API fits the current Apache-2.0 component.

## Acceptance gate

Add a browser-level interaction check with enough fixture actions to overflow the pane. Repeated ArrowDown must keep the selected row inside the results viewport while focus remains in the search input. ArrowUp from the first row must expose the wrapped last row. Filtering back to a short list must expose its first result. Enter must execute exactly the selected action. This verifies actual layout and scroll behavior, which a mocked `scrollIntoView` unit assertion cannot establish.
