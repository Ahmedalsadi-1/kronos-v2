# Emulator swarm comparison

Source inspection only. AutoCua checkout at f104c6d5343dd80b64bb02276446131602311970, MIT (LICENSE:1–12). No SDK or emulator commands run and no timings measured.

1. **Android requires instance identity before adopting the upstream launch strategy.** AutoCua prepares a shared snapshot-capable AVD once, then spawns independent headless read-only copies (AutoCua/agent_launcher.py:917–955, AutoCua/android_connector/emulator.py:667–736, 789–818). This is a disk/bootstrap template, not a persistent pool of booted clones. The console/ADB pair is checked against ADB and socket availability and guarded by process-local state plus OS file locks (:490–546). Each child receives its exact serial (agent_launcher.py:988–998). KronOS discovers the serial but keys any emulator with a resolved name by AVD name, and boot and connected-device lookup take the first matching ID (emain/device-simulator/android/android-simulator-service.ts:99–126, 144–205). Same-AVD copies would alias in routing, locks, and assignments. Add explicit managed instance identity bound to launch generation and observed serial before enabling copies. Keep legacy AVD profile IDs as boot selectors and reject ambiguous routing. Test two same-name AVDs with reversed inventory order, port contention, and serial reuse after restart.

2. **Keep existing iOS per-UDID control and borrow lifecycle ideas.** AutoCua excludes already chosen UDIDs inside a run, allocates a sequential WDA port plus separate MJPEG port and builds per slot, then starts one activation thread per task (AutoCua/agent_launcher.py:692–735; AutoCua/ios_connector/sim_session.py:502–513, 739–805). Resolver can create devices with simctl when needed (:312–345, 429–482), but this is neither cloning nor a cross-run device lease. The port probe does not reserve an ephemeral MJPEG socket through WDA startup. Finally cancels/reaps activations, but deactivate shuts down its recorded UDID without checking whether a user pre-booted it (agent_launcher.py:875–897; sim_session.py:843–868). KronOS already coalesces per-UDID attach and runs serve-sim/retains frames (emain/device-simulator/ios-simulator-control.ts:86–167). Preserve that backend. Track scheduler-owned boots and support opt-in prewarmed disposable UDIDs. Test two concurrent reservations, partial stream readiness failure, and cancellation with an unrelated pre-booted simulator.

3. **Budget globally and make owned-resource cleanup a separate policy.** KronOS provides bounded async batches (1–4 workers each, up to four running batches) but no shared boot-token limit across batches or resident emulator budget (emain/device-farm-batches.ts:27–69). Cancellation drains queued items only, leaving running boots and successful assignments (same file:82–91). Assignment records bind caller and generation, and per-target busy sets guard actions (emain/device-farm-runtime.ts:22–46, 155–189). AutoCua creates a boot thread per task and gates child starts on group readiness, with best-effort cleanup and a parent-death watchdog for Android (agent_launcher.py:940–959, 1071–1082; emulator.py:814–818, 864–924). Use a single host budget for launch and resident resources, dispatch each ready slot, and add abortable lifecycle for task-owned targets only. Test simultaneous batches, cancellation at spawn/ready/assignment boundaries, cleanup errors and user takeover. Retain the existing explicit-target batch semantics for user-provided devices.

4. **Remove full fleet enumeration from hot paths and share preview work.** Assigned actions can enumerate twice: authorization calls full list, then runtime resolve calls it again (emain/device-farm-runtime.ts:22–43; emain/computer-targets-runtime.ts:208–220, 252–276). The calls are asynchronous, but full list awaits simctl, Android discovery and optional Appium in sequence, with AVD-name probes per online emulator (:114–120, 162–192; emain/device-simulator/android/android-simulator-service.ts:99–126). IDs are checked exactly, so this is a latency/fanout concern rather than an explicit fallback to a different target, apart from Android aliasing above. Preview uses an existing exclusive target lease and iOS latest-frame stream, whereas Android invokes adb screencap per frame (emain/computer-target-sessions.ts:25–103; emain/computer-targets-runtime.ts:428–437; android-simulator-service.ts:217–221). Coalesce inventory refresh and use per-target health/generation checks at dispatch. Give visible subscribers a bounded shared latest-frame producer while keeping action evidence fresh. Test one bad backend cannot stall unrelated control, one capture producer per active target, no stale action after reconnect, and no capture backlog after the last subscriber leaves.
