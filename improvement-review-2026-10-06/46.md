# 46 - Tsunami engine: make effect dependency comparison safe

Priority: P1 for engine reliability; confirm actual component usage before scheduling ahead of user-visible failures.

The strongest focused improvement is to define and enforce a safe dependency contract for Go `UseEffect`. The engine accepts arbitrary dependencies as `[]any`, but `depsEqual` compares their interface values directly at `tsunami/engine/hooks.go:112-120`. A second render containing a slice, map, or function of the same dynamic type can panic at line 117 because these Go values are not comparable. `UseEffect` calls this comparison at line 145. The render error guard at `tsunami/engine/render.go:183-187` can turn this into an error component; recovery does not make effect semantics correct.

Observed: unrestricted dependency input and direct interface inequality exist in the inspected source. Hypothesis: application components pass non-comparable dependencies frequently enough to produce visible failures. No production incident, reproduction, or full usage audit was performed. No `_test.go` files appear in the inspected engine directory inventory. That observation does not establish that other directories lack integration coverage.

Plan: first inventory effect dependency call sites. Specify equality for scalar values, pointers, typed nils, and unsupported composite values. Prefer a documented comparable-value or explicit-version-token contract with a descriptive validation error over silently adding deep equality. Deep equality can hide mutation, adds runtime cost, and changes the intended identity model. Validate before committing the hook's dependency snapshot; copy the dependency slice so a caller cannot rewrite the previous snapshot in place. Preserve the documented distinction between nil dependencies (every render) and an empty non-nil slice (mount only).

Established references: [React](https://github.com/facebook/react) supplies the mature effect dependency/lifecycle model; [Go](https://github.com/golang/go) supplies the language/runtime comparability contract. Both are already verified upstream entries in `upstream-catalog.md`; React is MIT and Go is BSD-style. These are behavioral references, not a recommendation to port JavaScript equality literally into Go or add a dependency. Fresh browsing was unavailable under the review's network permission block; specific upstream implementation paths and commit provenance must be checked before implementation.

Acceptance gate: table-driven engine tests cover equal/changed scalars, typed nils, slice/map/function inputs without an uncontrolled comparison panic, caller mutation of the original dependency slice, nil versus empty dependencies, and exactly-once cleanup before rerun/unmount. Run the relevant Go tests, then exercise a Tsunami component through repeated updates and unmount. No builds or product edits were made in this review.
