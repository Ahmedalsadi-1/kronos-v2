# 42. RPC contracts: compatibility gate before expanding commands

Priority: P1. Strongest improvement: produce a deterministic RPC contract manifest from the existing Go source of truth, and compare it against the previous release in CI. Keep the current JSON/WebSocket protocol and generator; adopt the compatibility-checking practice demonstrated by Buf rather than migrating transports.

Observed: `pkg/wshrpc/wshrpcmeta.go:68` derives command identifiers and argument/response types from reflection. At line 79, a method name becomes the lowercased wire command; renaming a Go method therefore also changes its wire identity. `pkg/wshrpc/wshrpctypes.go:410` defines CreateBlock arguments with explicit JSON names, optional fields, and a string-valued action whose allowed values appear only in a comment at line 418. `pkg/wshrpc/wshrpcmeta_test.go:18` tests multi-argument declaration generation, but the sampled tests do not establish released wire-shape compatibility. `cmd/generatets/main-generatets.go:129` consumes the declaration map to generate frontend APIs. Nearest package instructions explicitly prohibit editing those generated clients.

Hypothesis: independently updated remote helpers, managed agents, or cached clients can encounter a renamed command, altered field type, or changed optionality before compile-time checks reveal the mismatch. This review did not reproduce an actual incompatible release and did not inspect every CI job; absence of a repository-wide compatibility gate remains to be confirmed.

Proven source and fit: [bufbuild/buf](https://github.com/bufbuild/buf) implements release-baseline comparison and distinguishes source, JSON, and wire compatibility. Its [primary documentation](https://buf.build/docs/breaking/) describes breaking-change checks against earlier schema versions. The repository [license](https://raw.githubusercontent.com/bufbuild/buf/main/LICENSE) is verified Apache-2.0. Buf itself requires Protobuf and is not a drop-in checker for these reflected Go JSON contracts. Reuse its baseline/rule-category approach, implemented narrowly in KronTerm's generator; avoid a broad schema migration. No upstream code needs copying.

Implementation sequence: (1) Export sorted command names, call/stream kind, argument order, response shape, JSON field tags, nested field types, and omission rules. (2) Check in the first release baseline and write explicit policy for additive optional fields versus removals, renames, type changes, and stream-kind changes. (3) Add old-payload/new-server fixtures for CreateBlock and one response-stream command, including omitted optional fields. (4) Require an explicit compatibility exception and release note for intentional breaks. Add a clean-generation check for frontend and Go client outputs.

Gate: a deliberate command rename, JSON field rename, argument reorder, and call-to-stream mutation must fail compatibility checks; adding an optional field must pass. Existing release payload fixtures must still decode and execute appropriately. Run targeted package tests and generator drift checks during implementation, never manually edit generated outputs or run Go builds. Expected benefit is earlier detection of remote/client breakage; no latency improvement is claimed.
