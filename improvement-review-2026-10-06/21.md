# 21 - Terminal renderer: preserve xterm binary input

Priority: P2. Confidence: high for the missing subscription; medium for user-visible frequency. This is a narrowly scoped compatibility improvement, not a recommendation to replace the renderer.

## Local evidence

`/Users/albsheralsadi/kronterm/frontend/app/view/term/termwrap.ts:406` subscribes to `terminal.onData`, but this directory contains no `onBinary` subscription. `termwrap.ts:534` forwards ordinary strings through `sendDataHandler`; `term.tsx:355` connects that callback to the model. `/Users/albsheralsadi/kronterm/frontend/app/view/term/term-model.ts:550` encodes controller input with `stringToBase64`. Its implementation at `/Users/albsheralsadi/kronterm/frontend/util/util.ts:42` uses `TextEncoder`, appropriate for text but unsuitable for a binary string whose code units represent bytes above 127.

Observed: the integration exposes only the text event path. Upstream explicitly defines a separate binary event for non-UTF-8 mouse reports. Hypothesis: applications using those reports lose mouse input when xterm emits `onBinary`. No live terminal reproduction was performed; common modern SGR mouse protocols may avoid this path, so the finding should not be generalized to all mouse interaction.

## Established upstream and fit

Verified primary source: [xterm.js 5.5.0 public API](https://github.com/xtermjs/xterm.js/blob/5.5.0/typings/xterm.d.ts), specifically `Terminal.onBinary` and its byte-preserving PTY guidance. This version matches the repository's declared `@xterm/xterm` baseline in `package.json:122`. The [current public API](https://github.com/xtermjs/xterm.js/blob/master/typings/xterm.d.ts) retains the distinction. The [upstream license](https://github.com/xtermjs/xterm.js/blob/master/LICENSE) is MIT; retaining notices is compatible with this existing dependency.

Adopt the existing public event, with a distinct binary callback that converts each code unit to a byte and uses the existing array-to-base64 utility. Keep Unicode text on its current UTF-8 path. Register the returned disposable in `toDispose`. This needs no new library or upstream fork; maintenance is limited to the callback boundary and regression coverage. Current-source verification establishes continuing API support, not a promise about release cadence.

## Acceptance criteria and test gate

- An emitted binary payload containing `0x80` and `0xff` reaches `ControllerInputCommand` unchanged after base64 decoding, exactly once.
- Unicode typing and paste retain UTF-8 encoding; binary input bypasses IME text suppression.
- Disposal removes the binary listener, and loading behavior is explicitly consistent with the existing input guard.
- Decide and document whether binary mouse input participates in multi-input; do not silently convert it through the text broadcast handler.

Gate adoption on focused Vitest coverage of both event paths and disposal, extending `termwrap-lifecycle.test.ts`, plus a real PTY mouse-report reproduction. Suggested command: `npx vitest run frontend/app/view/term/termwrap-lifecycle.test.ts`. Tests and builds were not run during this read-only review; only this report was created.
