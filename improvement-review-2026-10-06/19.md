# 19 - Keyboard ownership and composition

Priority: P2. Add a composition ownership guard to the core keyboard dispatcher before chord matching. This is a focused correctness improvement; no replacement keyboard library is recommended.

Observed: `frontend/app/store/keymodel.ts:421` checks disabled bindings, selector ownership, HUD ownership, and duplicate native events, then matches chords at line 432 and global shortcuts at line 453. None of those gates checks IME composition. An active chord with an unmatched second key returns true at lines 441-444, consuming that key regardless of composition ownership. `frontend/util/keyutil.ts:231` adapts React/native keyboard events without retaining `isComposing`; the Electron adapter at line 252 also has no composition state. Native event access is available but is currently used only for ownership and deduplication. In contrast, `frontend/hermes/lib/keybinds/combo.ts:115` rejects composing events and Process keys, and `frontend/hermes/app/hooks/use-keybinds.ts:313` also guards composition. The sampled Hermes path already addresses this concern.

Hypothesis: a composition-owned key can reach core shortcut or block dispatch, particularly when chord state is active. This review establishes the missing guard and consumption branch, not a reproduced user-visible IME failure. Real Electron input sequences and native reinjection still need verification; avoid claiming that every IME produces shortcut modifiers.

Verified primary reference: Microsoft VS Code's [AbstractKeybindingService](https://github.com/microsoft/vscode/blob/main/src/vs/platform/keybinding/common/abstractKeybindingService.ts) checks composition before both dispatch and soft dispatch. Its [test suite](https://github.com/microsoft/vscode/blob/main/src/vs/platform/keybinding/test/common/abstractKeybindingService.test.ts) contains a composition regression asserting no command or prevention while composing and normal execution after composition. Both files were fetched on 2026-10-06. They provide a concrete source/test gate, not evidence that KronTerm passes it. Upstream is MIT licensed, as its source header states.

Acceptance criteria: composing Enter, Space, arrows, Escape, and Process events invoke no core action and remain available to the text input; a composing key during an active split chord is not consumed; noncomposing shortcuts and chord timeout behavior remain intact. Test native and React adapters, including React's underlying native event, then manually exercise Chinese/Japanese composition in Hermes and a terminal. Determine an explicit policy for Electron reinjection where composition metadata is unavailable.

Adoption/maintenance: implement a small shared ownership predicate and preserve composition metadata at boundaries; adapt the upstream test behavior rather than importing VS Code's service dependencies. Keep existing compatibility key syntax and platform mappings. Any copied MIT code requires attribution; independently implementing the behavioral contract adds no dependency. No builds, tests, or product edits were performed for this read-only review.
