## P1: Validate an entire resize action before mutating the tree

**Observed:** `frontend/layout/lib/layoutTree.ts:380-391` logs a missing `resizeOperations` array but continues into iteration, which throws. It validates and mutates operations one at a time: a valid first operation followed by an out-of-range second operation returns after the first mutation. A nonexistent node ID passes the string/range check and then dereferences the missing node at line 390. `NaN` passes both range comparisons and is stored. These are direct code-path findings, not reproduced runtime reports.

**Hypothesis:** A stale drag action after a pane removal, or malformed restored/programmatic state, can cause an exception or partly changed geometry. Normal pointer-generated actions may avoid these inputs; caller reachability and user-visible frequency remain unverified. The fix should defend this reducer without assuming all invalid data is currently reachable.

**Acceptance:** Preflight collection shape, finite numeric sizes, allowed range, and every referenced node before assigning any size. Reject invalid actions with no exception and no change to any node. Keep existing valid action semantics; do not impose a new sibling-total invariant until the layout weight model is confirmed.

**Test gate:** Extend `frontend/layout/tests/layoutTree.test.ts` (currently no `resizeNode` cases found) with missing operations, unknown IDs, `NaN`, infinities, an invalid second operation, and a valid paired resize. Assert unchanged sizes on rejection and expected sizes on success. Run `npx vitest run frontend/layout/tests/layoutTree.test.ts` before acceptance.
