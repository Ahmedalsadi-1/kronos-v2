"What is KronOS?"
"KronOS is a desktop workspace that brings terminals, browsers, files, previews, remote sessions, and KronOS Agent together. Arrange the same tools in OS, Canvas, Tabs, or Widgets mode."
"Is this the same project as KronTerm?"
"Yes. KronOS is the current product name. The product has grown from a terminal workspace into a shared desktop for you, your tools, and your agent."
"How does KronOS Agent fit into the workspace?"
"KronOS Agent is the built-in chat and agent surface, backed by the managed Hermes runtime. Work in full chat or alongside your canvas, and use /files, /terminal, and /preview to bring workspace context into the conversation."
"Can I keep using my terminal and remote sessions?"
"Yes. Terminals and SSH connections are part of the workspace alongside browsers and files. You can choose a focused tab, a tiled split, or a spatial arrangement for the task."
"What is available to download?"
"The linked release is the KronOS 0.14.5 public preview for Apple silicon Macs. Check the download page for requirements and release notes. The iPhone client and phone-control bridge are Labs work."

"workspace-is-the-context"
"Field note 01"
"July 2026"
"6 min read"
"The workspace is the context."
"Why agent work improves when the terminal, product, files, and decisions remain visible in the same operating picture."
"A transcript is only a shadow of the work"
"Most software work does not happen in a prompt. It happens across a running process, an open diff, a browser state, a remote machine, and a series of decisions that rarely fit cleanly into one message."
"When an agent only receives a transcript, the person directing it becomes a human context bridge. They copy the failure, describe the open page, paste the file, and explain which environment is safe to touch."
"Keep the evidence where the action happened"
"KronOS treats the workspace as the durable unit of context. Blocks preserve the spatial relationship between commands, source, previews, sandboxes, and agent sessions."
"The goal is not maximal automation. It is a legible loop where a person and an agent can inspect the same evidence, act on the same surface, and understand what changed."
"browser-automation-should-leave-evidence"
"Field note 02"
"July 2026"
"5 min read"
"Browser automation should leave evidence."
"A browser action is more trustworthy when the page state, target, screenshot, and resulting product behavior stay attached to the task."
"Coordinates are not an explanation"
"A click at x and y can reproduce an action, but it does not explain the target or survive a small layout change. Structured element references give browser work a vocabulary that people and agents can share."
"KronOS’s Widget Protocol exposes visible controls as stable references, while screenshots preserve the visual result that a selector alone cannot describe."
"Validation belongs beside implementation"
"The browser is where assumptions about layout, state, authentication, and customer flow become visible. Keeping it beside the terminal and source compresses the distance between a change and its proof."
"An agent can inspect a page, operate a scoped flow, capture the result, and connect that evidence back to the command or file that produced it."
