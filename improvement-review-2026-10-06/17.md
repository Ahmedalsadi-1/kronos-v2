## Priority 1 (P2): reconcile removed custom properties on persistent hosts

Observed: [persistent-block.tsx:89](/Users/albsheralsadi/kronterm/frontend/app/block/persistent-block.tsx:89) replaces the host's complete inline style only when the geometry CSS string changes. Lines 94-96 then copy every custom property exposed by the slot's computed style. There is no corresponding removal for custom properties that disappear from the slot. Because the host DOM intentionally survives presentation changes, a property copied during one ownership period can remain inline during another when geometry is identical. An inline stale value can also override newly inherited theme values. Geometry changes happen to clear it through `cssText`, making correctness depend on movement.

Hypothesis: equal-size presentation changes or theme updates can retain obsolete colors/spacing. No visible production failure was reproduced; computed-style enumeration and the applicable theme variables need a real-browser regression fixture. This is a concrete missing reconciliation branch, not evidence that every presentation transition is affected.

Recommended implementation: track the names of previously copied custom properties, remove names missing from the next snapshot, and set only changed values. Keep ownership explicit so unrelated host properties are never cleared.

Acceptance criteria and test gate: give slot A `--review-accent:red`, move the same live block to equal-geometry slot B without that property, and assert the host's inline declaration is absent and B's inherited value wins. Assert the input DOM identity and mount count remain unchanged; repeat after a theme update and after HUD preview restoration. Extend `persistent-block.test.tsx` ownership coverage, then run its targeted Vitest suite; use a browser check for computed inheritance because jsdom is insufficient evidence.

## Verified upstream pattern and fit

React's [CSSPropertyOperations.js](https://github.com/react/react/blob/main/packages/react-dom-bindings/src/client/CSSPropertyOperations.js) explicitly clears previous custom properties absent from the next style map before applying new values (`setValueForStyles`, lines 126-147). Adopt that reconciliation principle locally, not React internals. Its [repository](https://github.com/react/react) has extensive adoption (51.4k forks observed) and maintained source; KronTerm already declares React `^19.2.0`. React uses the [MIT license](https://github.com/react/react/blob/main/LICENSE), compatible with this Apache-2.0 source; no dependency addition or wholesale source copying is needed. Main-branch links were verified on 2026-10-06 and should be pinned if copied into implementation documentation.
