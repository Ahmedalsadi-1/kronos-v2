# Review 13/50: HUD controller

Scope: read-only sample of `frontend/app/workspace/kronterm-hud-controller.ts` and its tests; root AGENTS.md applies. No builds or product changes. Findings below are source observations, not reproduced desktop failures.

## Priorities

1. **P2: Make island admission and restoration obey the same contract.** Observed: `/Users/albsheralsadi/kronterm/frontend/app/workspace/kronterm-hud-controller.ts:19` filters IDs and retains at most 40, while `:95` accepts any ID and an unlimited number when active. Consequently the live and reloaded snapshots can differ; registering 41 valid unique IDs persists all 41, then restoration retains only 40. Hypothesis: a heavily populated HUD loses detached-widget membership after switching workspaces/restarting. Acceptance: explicitly choose the limit and apply one normalization policy to both mutation and hydration; a 41-island round trip must preserve the chosen behavior, and invalid IDs must be handled consistently. Do not silently limit registration after widget creation without coordinating its caller.

2. **P3: Separate durable updates from notification.** Observed: `:89` selection and `:114` background changes call `emit`; `:158` synchronously rewrites the complete island list and placement preference on every notification, although neither field changed. Hypothesis: frequent focus/background transitions cause avoidable storage work; no latency was measured. Acceptance: selection/background-only changes perform zero storage writes; island and placement changes persist their changed keys; rejected storage writes still notify subscribers. Retain immediate persistence for actual durable changes unless measured traffic justifies batching.

## Verified upstream pattern and fit

[pmndrs/zustand](https://github.com/pmndrs/zustand) is an established reference: GitHub displayed approximately 58.8k stars, 2.2k forks and 1,382 commits, plus source, tests, documentation and contribution instructions when checked. These are adoption/history signals; the fetched page did not expose a latest release date, so current maintenance recency is unverified.

Its [vanilla store source](https://github.com/pmndrs/zustand/blob/main/src/vanilla.ts) offers immutable snapshot updates and subscriptions; its [persist middleware](https://github.com/pmndrs/zustand/blob/main/src/middleware/persist.ts) exposes `partialize`, version and migration hooks. Borrow the explicit durable-state projection and hydration boundary as design references. `partialize` alone does not promise fewer writes; dirty-key comparison remains necessary for priority 2. Neither upstream primitive automatically solves the island policy mismatch.

The [MIT license](https://github.com/pmndrs/zustand/blob/main/LICENSE) permits reuse subject to preserving notices. Adding another state library solely for this 173-line controller would conflict with the repository's established Jotai model direction and add migration/maintenance costs; prefer improving the existing controller or using existing Jotai facilities. Pin a commit and retain attribution if copying upstream implementation.
