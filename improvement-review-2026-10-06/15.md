# 15 — Widget tab keyboard focus

Strongest finding (P1): arrow navigation selects a widget and transfers focus into its content instead of keeping keyboard focus in the tab strip.

Observed: `frontend/app/tab/widget-tabs-layout.tsx:943` handles ArrowLeft/Right and Home/End through `focusByIndex` (`:686`). That calls `focusNode` (`:647`), which schedules `refocusNode(blockId)` on the next animation frame (`:655`). The tab button uses roving `tabIndex` (`:228`), but this path never focuses the destination tab button. This mixes tab navigation with entering the widget. Hypothesis requiring an Electron interaction check: the first arrow press moves focus into a terminal/editor, so the next arrow press edits or navigates content instead of traversing tabs.

Acceptance: with three terminal/editor/browser tabs, focus the selected tab and press Right twice; DOM focus and selection must reach tab three, with no content keystrokes. Home/End and wraparound must retain tab focus. Enter or a documented separate action should enter widget content. Preserve the shared persistent block owner.

Additional priorities:

- P2: modified arrows are intercepted at `:943` without checking Ctrl/Meta/Alt/Shift. Verify conflicts with desktop shortcuts; acceptance: modified navigation reaches the existing shortcut owner unless explicitly reserved for tab actions.
- P2: pinned tabs expose an always-tabbable unpin button (`:278`), whereas inactive close buttons receive controlled accessibility state (`:262`). Audit intended tab-strip traversal. Acceptance: keyboard traversal has a documented, consistent route to pin/close actions and does not require visiting every inactive pinned tab action.

Verified upstream pattern: [Radix roving-focus source](https://github.com/radix-ui/primitives/blob/main/packages/react/roving-focus/src/roving-focus-group.tsx) tracks the current tab stop, maps arrow/Home/End to candidate element refs, explicitly focuses candidates, and excludes modified navigation. [Tabs source](https://github.com/radix-ui/primitives/blob/main/packages/react/tabs/src/tabs.tsx) composes roving focus with selection. Adopt the separation of tab focus and selection locally; replacing persistent panels with library-mounted content would need care.

Maintenance/adoption evidence: the [public repository](https://github.com/radix-ui/primitives) identifies WorkOS maintenance and approximately 1.3k forks at review time; current source includes a linked focus/hydration bug fix (issue 3077). These are maintenance/reuse signals, not proof of suitability. Its [MIT license](https://github.com/radix-ui/primitives/blob/main/LICENSE) permits reuse with notice retention; React/TypeScript fits KronTerm. No new dependency is necessary to adopt the focus algorithm.

Scope: focused static sample and upstream source inspection; no builds or runtime verification.
