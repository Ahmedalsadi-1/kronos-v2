# 06 — Hermes runtime supervision

Scope: read-only review of `emain/hermes-runtime.ts`; nearest `emain/AGENTS.md` read. No build or product edits.

## Strongest finding — P1: permanent failures cause unlimited restart attempts

**Observed:** `/Users/albsheralsadi/kronterm/emain/hermes-runtime.ts:395` schedules another startup after every current-generation failure; `:486–493` uses a constant one-second delay with no failure budget or backoff. Missing Hermes/KronosCode executables throw before spawning (`:560–564`), so an installation failure repeatedly performs executable discovery and logs indefinitely. Post-ready exits also use this policy (`:704–713`).

**Hypothesis:** repeated filesystem probes, synchronous PATH lookups (`:126`) and plugin preparation could make a broken installation noisy and degrade Electron responsiveness. No runtime measurements were performed.

**Improvement:** introduce capped exponential backoff, a consecutive-failure budget, and explicit degraded/repair-required state. Reset the budget only after a sustained healthy interval; let a deliberate repair/retry action reset it immediately. Keep single-flight startup and generation cancellation.

**Acceptance:** fake-clock tests show increasing delays and a bounded attempt count for missing executables and immediate exits; stable uptime resets failures; stop cancels retries; explicit retry recovers after installation repair. Report the last failure and next retry time through the existing connection/health communication boundary.

## Supporting improvement — P2: supervise exit throughout readiness checking

**Observed:** the early exit listener is removed when the ready marker arrives (`:639–641`); the persistent exit listener is installed only after awaiting HTTP health (`:675–704`). A child exit during that interval has no lifecycle handler. There is no child liveness check immediately before publishing the descriptor (`:691–703`).

**Hypothesis:** a successful health response racing a process exit could publish a dead connection and miss automatic restart until another caller invokes ensure.

**Acceptance:** install generation/child-scoped exit handling immediately after spawn and retain it across all startup stages. A deterministic ready → health pending → exit → health success test must never publish a descriptor and must schedule exactly one retry.
