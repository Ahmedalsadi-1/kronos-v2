# 05 - Agent runtime

Scope: `emain/kronoscode-runtime.ts`; read `emain/AGENTS.md`. Source-only review; no builds or application changes.

## Strongest finding: P1 - backend path guard permits an origin escape

**Observed:** `api()` rejects paths without `/` and paths beginning `//` at `emain/kronoscode-runtime.ts:595-598`, then resolves the accepted string with `new URL()` at line 601 and attaches backend Basic credentials at lines 605-613. A slash followed by a backslash is accepted. A local Node URL-only check confirmed `new URL("/\\example.com/path", "http://127.0.0.1:7777/").href` becomes `http://example.com/path`. No network request was made. The renderer-facing IPC handler forwards input directly (`emain/emain-ipc.ts:1119-1120`).

**Impact hypothesis:** A caller able to supply this API path can send a request and the runtime's Authorization header to an unintended host. This includes bypassing the non-loopback TLS requirement in endpoint validation. Exploitability depends on access to the IPC caller; credential forwarding follows directly from this method's source.

**Improvement:** Compare the resolved URL's origin to the validated connection origin before constructing credentials or fetching. Reject backslashes and URL credentials as additional input hygiene. Decide an explicit redirect policy for the credential-bearing proxy.

**Acceptance:** Tests reject slash-backslash and control-character authority variants, prove no fetch occurs on an origin mismatch, and retain ordinary absolute paths and query strings. An integration fixture confirms no Authorization reaches a second origin.

## P1 - handle spawn errors as startup failures

**Observed:** `launchManaged()` spawns at line 390 and installs handlers at 420. `attachChildHandlers()` (327-343) listens to output and `exit`, but never `error`; `waitForReady()` (301-325) polls exitCode/killed and the readiness file. An executable access check (124-134) does not guarantee its interpreter exists or that it remains executable when spawned.

**Impact hypothesis:** ENOENT/EACCES or an invalid interpreter can emit an unhandled child error instead of rejecting startup cleanly. No failed-spawn execution was attempted in this review.

**Improvement:** Attach an error listener immediately and race readiness against a child-start/exit/error promise, retaining generation cancellation and cleanup. Preserve useful spawn diagnostics in boot progress.

**Acceptance:** Missing interpreter and access-race fixtures reject promptly, publish error progress, clean temporary files, leave no child/connection, and generate no uncaught error.

## Verified transferable upstream

[Execa](https://github.com/sindresorhus/execa) is an established Node process library: the inspected repository shows 848 commits and roughly 1.9k forks, plus dedicated tests and error/termination documentation. Its [wait-subprocess source](https://github.com/sindresorhus/execa/blob/main/lib/resolve/wait-subprocess.js) races subprocess errors with completion; [exit-async](https://github.com/sindresorhus/execa/blob/main/lib/resolve/exit-async.js) explicitly handles failure before spawn, when exit never arrives. Adopt that narrow lifecycle pattern, without requiring a dependency migration. Its [MIT license](https://github.com/sindresorhus/execa/blob/main/license) fits this Apache-2.0 project; copied code requires retaining attribution.
