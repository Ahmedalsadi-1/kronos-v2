# 40 / 50 - Mobile Labs client

Scope: `mobile/` is the experimental iPhone Labs client, not a generally available desktop feature. Read `mobile/AGENTS.md`; sampled host persistence and its startup/connect/remove callers. No product files changed and no builds or tests executed.

## Strongest improvement: preserve paired hosts across storage failures

**Priority: P1 for the Labs release gate; effort: small to medium.** Introduce an explicit host-storage load state (`loaded`, `unavailable`, `corrupt`) and permit writes only after a successful read or an explicit recovery/reset choice. Retry unavailable native storage when the app becomes active/unlocked. Retain the current secure-storage dependency and device-only keychain policy.

**Observed:** `mobile/src/lib/host-store.ts:83` converts every read failure into an empty list. Reads include both native Keychain operations (`:28-30`) and browser JSON parsing (`:32-33`). `mobile/src/app.tsx:218` accepts that empty list as successful startup and `:222` marks loading complete. Connecting another host subsequently serializes the current in-memory list at `:569`; removing a host writes it at `:597`. Native writes use `whenUnlockedThisDeviceOnly` at `host-store.ts:41`. The file inventory did not show a dedicated host-store test file. Existing lifecycle and client tests are useful foundations.

**Hypothesis, not reproduced:** a transient native read rejection, or malformed browser serialization, can hide previously paired hosts. If the user then adds a host while storage is writable, a successful write can replace the saved collection with the incomplete list. The exact native failure timing needs device validation; this review does not claim that data loss has happened in production.

## Proven upstream pattern and fit

The already-adopted [aparajita/capacitor-secure-storage](https://github.com/aparajita/capacitor-secure-storage) provides Capacitor 8 support, native iOS Keychain and Android Keystore storage, and separate native demo applications. Its [MIT license](https://github.com/aparajita/capacitor-secure-storage/blob/main/LICENSE) is permissive; retain notices if copying code. Its README explicitly documents native storage behavior and warns that its own web fallback is debugging-only. KronTerm already uses a separate sessionStorage branch, so replacing that branch with the upstream localStorage fallback would be a regression in token persistence policy. Adopt upstream native demo validation patterns, not a new storage library or an unreviewed migration.

## Implementation and acceptance gate

Add a narrow storage adapter that distinguishes absent keys from rejected reads; return state alongside validated profiles. Show a recoverable Labs pairing-storage error and block destructive persistence until recovery. Validate capability members and required profile fields before use. Add focused Vitest cases for missing data, malformed JSON, native rejection followed by recovery, and attempted save after failed read. On an actual iPhone, verify relaunch, lock/unlock, foreground resume, and retained pairing credentials. Gate broader Labs distribution on zero silent replacement of existing paired-host data; keep credentials out of logs and test fixtures.
