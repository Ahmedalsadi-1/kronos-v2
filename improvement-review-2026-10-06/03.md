# 03 - IPC and preload

Scope: `emain/preload.ts`, `emain/emain-ipc.ts`; read `emain/AGENTS.md`. Read-only inspection; no builds or exploit reproduction.

## P1 - Authorize privileged IPC at the main-process boundary

Observed: `emain/emain-ipc.ts:503` returns arbitrary named environment variables; `:428` accepts any string for shell.openExternal; `:1100`, `:1119`, `:1123` ignore the event when proxying agent APIs and changing connection settings. These handlers contain no sender/frame authorization. Some other handlers correctly resolve a registered tab from event.sender (`:493`), so authorization is inconsistent. Remote-frame reachability and a working exploit are **unverified**, not asserted.

Plan: wrap registration with a policy that verifies live registered webContents, expected surface role, and senderFrame origin; runtime-validate payloads; replace arbitrary getEnv with explicit settings/environment allowlist and validate external URL protocols in main. Keep legitimate custom protocols only with documented policy.

Proven source: [electron/electron security guide](https://github.com/electron/electron/blob/main/docs/tutorial/security.md), sender validation and external URL sections. Borrow the boundary pattern, not a new dependency.

Acceptance: unregistered sender, guest frame, wrong surface role, malformed payload, non-allowed env key and unsupported scheme are rejected before side effects; ordinary main-window, pet and overlay scenarios retain approved capabilities. Tests exercise policy and handler dispatch.

## P1 - Make all preload event subscriptions payload-only and disposable

Observed: `emain/preload.ts:147` passes callback directly to ipcRenderer.on for onMenuItemAbout, unlike safer payload wrappers elsewhere. `:129`, `:140`, `:143` register listeners without unsubscribe functions; `:39-40` shows an existing working cleanup pattern. Actual listener growth or event-object abuse is **unverified**.

Plan: consistently create local wrapper functions which discard Electron event arguments and return removeListener closures; update ElectronApi types and callers to retain cleanup. Preserve method names for compatibility.

Proven source: [electron/electron ipcRenderer documentation](https://github.com/electron/electron/blob/main/docs/api/ipc-renderer.md) warns against exposing event arguments and defines removeListener; [IPC tutorial repository source](https://github.com/electron/website/blob/main/docs/latest/tutorial/ipc.md) demonstrates narrow contextBridge APIs.

Acceptance: no exposed API forwards IpcRendererEvent; repeated subscribe/unsubscribe returns each channel's listener count to baseline; component remount receives one callback per event.

## P2 - Reduce synchronous IPC on renderer hot paths

Observed: `emain/preload.ts:13-24`, `:118`, `:138`, `:144-145` use sendSync. This is a blocking mechanism; user-visible lag has **not** been measured.

Plan: collect immutable launch metadata once, use cached synchronous getters where compatibility requires them, and migrate changeable queries to invoke plus update subscriptions. Profile before widening the change.

Proven source: [electron/electron ipcRenderer documentation](https://github.com/electron/electron/blob/main/docs/api/ipc-renderer.md), sendSync warning and invoke API.

Acceptance: no recurring sendSync in interaction paths; initialization values and updates remain correct; trace demonstrates no synchronous main-process wait during menu/workspace interaction.
