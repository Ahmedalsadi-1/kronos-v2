## P2 - Keep main-frame failure state until recovery

**Observed:** `frontend/app/view/webview/webview.tsx:1586` handles every non-aborted `did-fail-load` event as a whole-browser failure. It does not inspect `isMainFrame`, although Electron supplies that field. At `:1592` it sets the error overlay; at `:1595` it invokes the optional failure callback. A failed embedded frame can therefore be promoted to a browser-level failure despite a usable main document. The callback also receives `getURL()` rather than the failing event's `validatedURL`.

**Observed:** `:1580-1584` clears error text on `did-stop-loading`. This event indicates that loading stopped, not that navigation succeeded. `:1541-1543` also clears errors and the favicon before checking whether a navigation belongs to the main frame. The failure overlay rendered at `:1760` consequently depends on event ordering rather than an explicit successful navigation transition.

**Hypothesis requiring Electron reproduction:** a DNS failure followed by loading-stop can briefly display and then erase the actionable failure overlay. A subframe failure can trigger the failure callback or obscure a successfully loaded page. These are source-supported risks, not claimed reproduced incidents.

**Proposed acceptance criteria:** a main-frame unreachable URL retains its failure message and retry action after loading stops; subsequent successful main-frame navigation clears it; failing iframes do not display the whole-page overlay or invoke the main-page callback; aborted navigation remains suppressed; unrelated subframe navigation preserves the page favicon. Add focused event-sequence tests plus one Electron integration fixture containing a successful parent and unreachable iframe. Existing `webview.test.tsx` samples model/preview behavior but does not exercise these registered event sequences.

## Verified reference and fit

[Electron webview API contract](https://github.com/electron/electron/blob/main/docs/api/webview-tag.md) specifies `isMainFrame` on failures and distinguishes loading-stop from navigation completion. [Electron's upstream webview integration suite](https://github.com/electron/electron/blob/main/spec/webview-spec.ts) is a primary reference for testing actual guest navigation rather than relying solely on React mocks. Both were retrieved during this review; the suite was inspected as a reference, not executed.

Electron is already adopted here (`package.json:49`, version range `^41.0.2`), so using its event contract adds no dependency. The public repository maintains API documentation and an extensive integration suite; confirm behavior against the project's installed version before implementation. [Electron's MIT license](https://github.com/electron/electron/blob/main/LICENSE) permits reuse with attribution. Prefer adapting test scenarios and event semantics rather than copying its harness. Broader WebContentsView migration is unnecessary for this bounded fix and would materially increase maintenance scope.
