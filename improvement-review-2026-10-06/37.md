# 37 - AI provider streaming lifecycle

Priority: P1. Make provider output delivery cancellation-aware and guarantee stream cleanup before broader provider SDK consolidation.

## Observed evidence

The sampled OpenAI completion adapter allocates an unbuffered output channel at `pkg/waveai/openaibackend.go:76`. Every response and error is delivered with a bare channel send, including the header at line 166, token packets at line 174, and panic recovery at line 81. The HTTP request receives the caller's context at line 147, but cancellation cannot release a goroutine already blocked on one of those sends. After stream creation there is no explicit `apiResp.Close()` before the receive loop at line 153. This is an observed implementation gap; whether users currently trigger accumulated goroutines or connections is a hypothesis requiring a cancellation reproduction. No production failure or leak measurement was performed.

Similar bare sends appear in Anthropic, Google, cloud, and Perplexity adapters. By comparison, `pkg/aiusechat/openai/openai-backend.go:540` already defers response-body closure. This indicates that a small common lifecycle contract is more appropriate than an immediate rewrite of both provider stacks. The nearest waveai and aiusechat AGENTS files were read; their referenced parent `pkg/AGENTS.md` is absent.

## Proven repository pattern and fit

The official [openai/openai-go repository](https://github.com/openai/openai-go) provides a concrete stream ownership pattern in [packages/ssestream/ssestream.go](https://github.com/openai/openai-go/blob/main/packages/ssestream/ssestream.go): terminal events and decoder errors run through `finish`, which calls `Close`; explicit early termination also has a public close operation. Closure uses `sync.Once`. Its [license](https://github.com/openai/openai-go/blob/main/LICENSE) is Apache-2.0, verified online on October 6, 2026. This is a primary provider-maintained implementation, not evidence that an SDK swap alone fixes KronTerm's channels. Adopt its explicit ownership/cleanup principle while keeping existing OpenAI-compatible and Azure configuration behavior; use the existing SDK's close method first. Any later SDK migration needs separate compatibility gates and a pinned reviewed version.

## Concrete improvement and gate

Introduce a provider-local send helper selecting between output delivery and `ctx.Done()`, including error and panic paths. Defer stream closure immediately after successful creation. Extend the contract across waveai adapters only after the OpenAI regression passes.

Use a local `httptest` SSE server: emit one valid chunk, stop consuming the output, cancel the context, and assert the producer exits and the server observes request termination within a bounded deadline. Also test normal EOF, malformed stream errors, cancellation before the first consumer read, and repeated completion cycles. Run `go test -race ./pkg/waveai/...` and the related aiusechat provider suites. Require unchanged packet ordering, model headers, finish reasons, and Azure/custom base-URL request behavior. No builds or code changes were made for this review.
