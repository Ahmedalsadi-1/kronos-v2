# 39. Agent activity evidence and overlays

**Priority: P2. Strongest improvement: make overlay expiry and presentation state belong to a specific run.**

Reviewed `frontend/types/agent-activity.ts`, `frontend/app/view/use-agent-overlays.ts`, their existing tests, and the nearest `frontend/app/view/AGENTS.md` (its referenced frontend parent does not exist). No product files changed or builds executed.

## Observed evidence

`frontend/app/view/use-agent-overlays.ts:66` clears and replaces the overlay expiry timer before checking whether a terminal-phase event belongs to `currentRunId` at line 78. A completion from a different run therefore changes the lifetime of the visible run even when its state update is rejected. Repeated unrelated completions can keep a stale cursor visible past its intended 15-second expiry. The running branch at line 101 replaces `currentRunId` but retains existing markers and cursor if the new activity supplies no point; markers from different runs can consequently coexist. These are direct control-flow observations; whether users regularly encounter them depends on overlapping runs targeting the same surface/block, which was not measured.

The tests in `frontend/app/view/use-agent-overlays.test.ts:16` exercise target matching only. They do not mount the hook or verify run changes and timer isolation. `frontend/types/agent-activity.ts:115` bounds entries per run but does not bound the number of retained runs. This is a secondary retention concern, not a measured memory leak: callers could clear timelines elsewhere.

## Proven repository pattern and fit

[Redux Toolkit listener middleware source](https://github.com/reduxjs/redux-toolkit/blob/master/packages/toolkit/src/listenerMiddleware/index.ts) tracks executing tasks independently, exposes cancellation scoped to controllers, and removes completed tasks in cleanup. Its [MIT license](https://github.com/reduxjs/redux-toolkit/blob/master/LICENSE) was verified online on October 6, 2026. Transfer the scoped-lifetime principle into the existing Jotai/React implementation; adding Redux would be disproportionate. This reference is a lifecycle pattern, not evidence that adopting a dependency fixes KronTerm.

## Implementation plan and gate

First extract a small overlay transition function with explicit run ownership. Reject unrelated completion events before mutating timers. Reset cursor, labels, and marker history when ownership changes; distinguish visual expiry from actual execution completion. Tie expiry callbacks to a generation/run token so stale callbacks cannot clear newer activity. Keep legacy phase normalization and surface/block filtering unchanged.

Acceptance gate: fake-timer tests prove run A expires on schedule despite run B completion; a point-free run switch removes run A's cursor; late callbacks cannot clear run B; unmount and target changes unsubscribe and cancel timers; existing legacy-normalization and targeting tests pass. Define concurrent-run presentation policy before shipping (last active run or separate per-run state). Follow up with a bounded completed-run retention policy and representative long-session heap measurement, rather than assuming a leak from the map alone.
